# TACTIC Handler Server

> Handler Server — локальный авторизованный маршрутизатор команд между самостоятельным Handler и
> тонкими DCC-клиентами. Его окно предназначено для оператора и диагностики, а не для обычного открытия или сохранения сцен.

## Что делает сервер

Handler запускает маршрутизатор отдельным локальным процессом на `127.0.0.1` и свободном порту. Для
каждого запуска создаётся новый случайный токен доступа. DCC runtime сам находит живую сессию Handler
и получает endpoint с токеном; пользователю не нужно вводить их вручную.

Сервер:

- авторизует каждого локального клиента;
- хранит client ID, тип приложения, PID и опубликованные возможности;
- отправляет запрос одному конкретному клиенту;
- возвращает структурированные результаты, ошибки и request ID;
- рассылает события подключения, отключения и исполнения скриптов;
- завершает ошибкой ожидающие запросы при исчезновении клиента или сервера.

Учётные данные TACTIC не являются данными DCC-подключения и не должны попадать в payload. Handler
Server не публикует веб-интерфейс в локальную сеть.

## Верхняя панель и жизненный цикл

| Элемент | Значение |
| --- | --- |
| Endpoint | Текущий loopback-адрес и автоматически выбранный порт. До конца запуска показан `localhost`. |
| Состояние | `STOPPED`, `STARTING`, `RUNNING` или `STOPPING`. |
| **Запустить** | Запускает маршрутизатор и подключает операторский клиент Handler. Запуск заканчивается после получения возможностей. |
| **Остановить** | Запрашивает штатную остановку. Клиенты и запросы отключаются; зависший процесс принудительно завершается после ограниченного ожидания. |

Остановка маршрутизатора не закрывает Handler, но DCC-действия недоступны до переподключения клиентов.

## Подключённые клиенты

Каждая строка соответствует одному процессу, а не просто типу приложения:

- **client ID** — точный адресат команд;
- **приложение** определяет Maya или другой DCC;
- **PID** различает одновременно запущенные сессии;
- **возможности** перечисляют принимаемые клиентом команды;
- **ACTIVE** отмечает цель ручной панели команд.

Выберите строку, чтобы заполнить список команд. **Отключить выбранный** разрывает только это соединение
и явно завершает его запросы ошибкой. Активный DCC runtime может подключиться снова.

Кнопка с кубом запускает или останавливает имитацию Maya-клиента. Она проверяет транспорт, не
запускает Maya и не проверяет реальное поведение сцены.

## Отправка диагностической команды

Правая часть окна — низкоуровневая командная консоль:

1. Выберите подключённый клиент.
2. Выберите одну из опубликованных им возможностей.
3. Введите JSON-**объект**; массивы и простые значения не принимаются.
4. Укажите тайм-аут от 1 до 300 секунд.
5. Нажмите **Отправить**.

Используйте `{}` для команды без параметров. Действию с путём обычно нужен подготовленный локальный путь:

```json
{
  "path": "D:/project/scenes/example.ma",
  "focus_application": true
}
```

Ручные команды обходят подготовку снапшота, репозитория и Очереди отправки. Используйте их только
для диагностики известной возможности, но не вместо штатного чекина.

## Результаты и журнал

Карточка содержит время, цель, действие и состояние. Ожидающий запрос показывает очищенный payload,
завершённый — сводку и структурированный результат, ошибка сохраняет удалённый traceback.
**Очистить результаты** очищает только список в этом окне.

Полное событие также записывается в Журнал отладки с тем же request ID. Пароли, тикеты, токены,
cookie и другие секретные поля удаляются перед логированием.

## Запросы из обычного интерфейса

Открытие, импорт, референс, сохранение, подготовка чекина, DCC-скрипты и триггеры используют тот же
маршрутизатор, но не требуют открытого окна. Целью служит клиент из верхней панели, а возможность
проверяется до отправки.

Для Maya Handler учитывает настройки возврата фокуса из **Настроек сцены Maya**. В Windows целевому
PID разрешается выйти вперёд; перед `open_scene` может быть отправлен `focus_application`, чтобы
вопрос Maya о сохранении не спрятался.

## Ошибки и состояния

| Сообщение или состояние | Что означает и что делать |
| --- | --- |
| **Handler Server не подключён** | Маршрутизатор ещё не достиг `RUNNING` или отключился операторский клиент. Запустите сервер и проверьте вывод. |
| **Выберите целевой клиент** | Перед отправкой выберите один подключённый процесс. |
| **Выбранный клиент не зарегистрировал действие** | Переподключите обновлённый коннектор или выберите клиент с нужной возможностью. |
| **Некорректный JSON payload** | Исправьте синтаксис; имена и строки должны быть в двойных кавычках. |
| **Payload должен быть JSON-объектом** | Замените список, простое значение или `null` на объект, например `{}`. |
| **Тайм-аут** | Проверьте нативное модальное окно и не заблокирован ли UI-поток DCC. |
| **Клиент отключён** | Точная цель завершилась или потеряла транспорт; работа не переназначается молча. |
| **Тайм-аут запуска** | Процесс не опубликовал корректный ready-ответ и возможности в срок. Проверьте Журнал отладки и вывод процесса. |

## Безопасная последовательность диагностики

1. Дождитесь `RUNNING` и запишите endpoint.
2. Проверьте приложение, сцену и PID.
3. Выберите клиент и найдите нужную возможность.
4. Отправьте безопасную команду чтения, например `get_application_info` с `{}`.
5. Сопоставьте результат с тем же request ID в Журнале отладки.
6. Повторите нативное действие из его штатного UI.

Подключение, скрипты, чекин и диагностика Maya подробно описаны в статье **DCC-клиенты**.
