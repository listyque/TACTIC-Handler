# Ошибки приложения

> Изменяемое по размеру модальное окно определяет категорию сбоя, а не показывает для каждой проблемы
> общую непредвиденную ошибку.

## Основные элементы

Разверните стек вызовов на оставшуюся высоту окна, выделите нужный текст или скопируйте полный стек
одной кнопкой.

Запрос показан с подсветкой Python и аргументами на отдельных строках. Многострочные значения,
включая серверные скрипты, вынесены в свои блоки с настоящими переносами строк. Имя
`request_text_N` в вызове указывает на соответствующий блок, а не меняет аргумент сервера.
Длинный код можно прокручивать по вертикали и горизонтали, выделять и копировать.
Полный исходный запрос остаётся без изменений в Журнале отладки.

## Как пользоваться

- При ошибке подключения окно поясняет, что сервер TACTIC недоступен, и предлагает проверить его
  адрес, сеть, VPN или прокси, а также убедиться, что сервер запущен.
- Техническая ошибка транспорта остаётся в стектрейсе и журнале отладки.
- Повторите доступную операцию, откройте нужные настройки или закройте ошибку кнопкой в футере.

## Что означает категория

Заголовок различает тайм-аут и отказ соединения, истёкший тикет, неверный вход, ошибку базы или
протокола, недоступный проект или файл, права, импорт, значение/тип/ключ/индекс, ОС, runtime,
assertion и QML. Понятный заголовок является подсказкой; исходные тип исключения и traceback без
изменений остаются в Журнале отладки.

## Как читать окно

1. Прочитайте сводку и имя неудачной операции.
2. Выполните предложенное действие, если оно есть.
3. Раскройте техническую часть, когда сводки недостаточно.
4. До закрытия скопируйте полный traceback для отчёта.
5. Найдите те же время или request ID в Журнале отладки для payload и команды.

## Ожидаемые состояния, а не ошибки

Отмена, пустой поиск, отсутствие DCC, необязательного превью или доступного офлайн-инструмента
показываются в своём окне и не должны открывать несвязанную Ошибку приложения.

## Ошибки DCC

Нативный вопрос DCC, диагностический вывод рендера или загрузки сцены остаётся в том приложении.
Handler показывает ошибку маршрутизации, тайм-аута, отключения клиента, подготовки локального файла
или структурированный сбой DCC. Для полного отчёта проверьте обе консоли.

## Перед повтором

Обновление только для чтения можно повторить после исправления соединения. До повтора записи убедитесь,
что первая попытка не успела создать снапшот, связь, объект или файл. Очередь отправки сохраняет
ошибочные строки для проверки точного состояния вместо слепого повтора.

## Окно не отвечает

Если цикл событий Qt не отвечает 15 секунд, Handler записывает стеки потоков Python и, в Windows,
нативный дамп процесса в локальную папку `log`. Имена файлов начинаются с `ui_hang_`; их можно
изучить после завершения процесса. Затем Handler запускает отдельное системное сообщение с путём
к дампу и закрывает невосстановимый процесс. Текст статей Базы знаний сохраняется отдельными
контрольными копиями, поэтому после повторного открытия проекта восстанавливается последний локальный
черновик.

Длинные строки запроса и стека переносятся по ширине окна ошибки и Debug Log.
Это предотвращает отрисовку одной огромной строки за пределами экрана после ошибки группового чекина.
Перенос меняет только показ: выделение и копирование с клавиатуры, «Копировать стек»,
«Копировать runtime-команду» и структурированный журнал сохраняют полный исходный текст.


## Просмотр ошибки и повтор операции

Разверните и скопируйте полный traceback, изучите запрос выполнения, откройте контекстную Help или Debug Log. Ошибки подключения подсказывают проверку адреса, сети и proxy. Историческое событие открывается только для чтения и не наследует команду повтора предыдущей живой ошибки. Handler показывает Retry только для операции, которую штатный владелец ошибки допускает повторить. Stream сохраняет существующие HTTP-уведомления об ошибках и открывает общие детали из Debug Log.
