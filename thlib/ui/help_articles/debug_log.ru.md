# Журнал отладки

> Журнал отладки собирает включённые уровни диагностических событий и сохраняет каждый запуск
> приложения как сессию с поиском.

## Основные элементы

Используйте фильтры уровней, дерево групп, текстовый поиск, детали событий, копирование команды
выполнения, выбор сессии, открытие сессии, возврат к текущей сессии, копирование пути и очистку
сессии.

## Как пользоваться

- Каждый запуск записывает одну компактную версионированную сессию JSONL.
- Короткие дисковые ключи разворачиваются в просмотрщике в понятные названия полей.
- Сообщения, детали, runtime-команды, тела скриптов, payload и traceback сохраняются без ограничения
  длины или глубины вложенности, чтобы записанную операцию можно было воспроизвести; поля с учётными
  данными по-прежнему маскируются.
- Успешные локальные вызовы настройки API, такие как set_server, пропускаются, а их ошибки
  сохраняются вместе с runtime-командой и traceback.
- В списке показывается и открывается только текущая схема сессии; заменённые форматы не
  загружаются.

## Фильтры расследования

Кнопки уровней объединяются с выбранной группой и текстовым поиском. Дерево групп считает события по
модулю и подсистеме с путём через `/`. Поиск проверяет сообщение, группу, модуль, функцию, runtime-
команду и traceback. Очистка одного фильтра не сбрасывает остальные.

Выбранное событие показывает время, уровень, модуль, функцию, строку, длительность, сообщение,
подробности, runtime-команду и traceback. Размеры панели групп и подробностей запоминаются.

## Текущая и сохранённые сессии

**Текущая сессия** продолжает принимать события работающего процесса. История или **Открыть сессию**
загружает `.jsonl` только для чтения. **Вернуться к текущей сессии** возвращает живой поток и не
объединяет старые события с новым запуском.

**Очистить сессию** очищает видимые живые записи. При просмотре сохранённого файла команда просто
возвращает текущую сессию и не меняет исторический файл.

## Воспроизведение и отчёт

1. Один раз воспроизведите действие.
2. Оставьте Error/Exception и нужную группу.
3. Выберите событие с совпавшими объектом, действием или request ID.
4. Скопируйте полное событие и при необходимости runtime-команду.
5. Скопируйте путь сессии, чтобы приложить исходный структурированный журнал.

Для DCC сопоставьте request ID в Handler, Handler Server и консоли DCC. Нативный вывод Maya не
переименовывается в ошибку TACTIC, но traceback маршрутизированной команды сохраняется.

## Приватность и хранение

Пароли, тикеты, токены, cookie и известные поля учётных данных маскируются до показа и записи на диск.
Не вставляйте секреты в обычные нетипизированные сообщения. Хранение сессий ограничено, но отдельное
диагностическое событие не обрезается молча.

Длинные строки запроса и стека переносятся по ширине окна ошибки и Debug Log.
Это предотвращает отрисовку одной огромной строки за пределами экрана после ошибки группового чекина.
Перенос меняет только показ: выделение и копирование с клавиатуры, «Копировать стек»,
«Копировать runtime-команду» и структурированный журнал сохраняют полный исходный текст.

## Серверный журнал RPC-запросов

JSON-вызовы `/admin/rpc` и XML-RPC-вызовы `/tactic/{project}/Api/` используют один logger `tactic_stream.server.api` на уровне **INFO** и исходный формат блоков TACTIC. Каждый вызов, дошедший до API-dispatcher, записывает один блок, включая завершившиеся ошибкой вызовы:

- `request_id`, `timestamp`, `user`, `simple method` и исходную шапку `ticket`;
- аргументы в порядке сигнатуры метода, включая полученные через JSON `kwargs`;
- `error` с классом исключения при ошибке;
- `Duration`, `Memory`, `Increment` и `Total Duration`.

`Duration` измеряет метод после инициализации API и авторизации. `Total Duration` измеряет весь вызов API-dispatcher; разбор HTTP-тела и сериализация ответа в этот таймер не входят. Пароли и известные секретные поля в аргументах маскируются. Шапка `ticket` сохраняет представление Legacy; этот серверный лог отличается от клиентского JSONL, где ticket маскируется. Отображение аргументов сохраняет существующие ограничения длины.

Другие адреса браузерного интерфейса, например `/admin/search-configuration/query`, не проходят через `/admin/rpc`. Их HTTP access-записи идут отдельно. Запросы, отклонённые до API-dispatcher, также не имеют блока метода.

Логирование не переключает транспорт ТХ. ТХ продолжает использовать XML-RPC, в том числе для подключения к Legacy TACTIC.


## Общее окно диагностики

Debug Log доступен с экрана входа и из меню приложения. Кнопки уровней фильтруют показ; запись уровней настраивается в Configuration. Стрелки вверх/вниз и Home/End в списке событий раскрывают нужную строку перед переводом фокуса. «Открыть детали события» показывает полное сообщение, команду и traceback; просмотр сохранённого события не повторяет операцию. Escape сначала закрывает это дочернее окно.

Откройте JSONL-сессию, выполните поиск, вернитесь к текущей сессии и экспортируйте её без изменения исходного файла. Handler копирует локальный путь, Stream скачивает JSONL и хранит историю в этом браузере. Выход из Stream закрывает дочерние детали, удаляет локальную историю и отклоняет импорт, завершающийся для прежней сессии. Длинные команды и результаты сохраняются полностью и прокручиваются по горизонтали.
