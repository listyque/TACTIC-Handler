# Окна и модальные редакторы

> Функциональные инструменты открываются в нативных окнах с оформлением текущей темы. Обычные окна
> могут работать рядом с проектом, а модальные редакторы блокируют владельца до применения или отмены операции.

## Справка и незавершённые жесты

Справка запоминает выбранную статью, поиск и отдельную позицию прокрутки каждой статьи при закрытии
и повторном открытии. Контекстная кнопка справки выбирает статью в том же окне. Поиск учитывает
содержимое статей. Перезагрузка перечитывает файлы и сохраняет позицию; смена языка при закрытой
справке применяется при следующем открытии. **Открыть файл статьи** открывает исходник,
**Скачать статью** сохраняет Markdown-копию. На узком экране кнопка **Разделы справки** переключает
список разделов и документ.

Плавающий док перемещается за заголовок; грип из шести точек используется для стыковки. Перенос
на заголовок другого дока меняет их местами, в центр — объединяет в табы, к краю — разделяет область.
Escape или отмена жеста возвращает прежнее положение или разделение, не принимая предварительный результат.

## Общее поведение окон

Каждое функциональное окно использует системную рамку для перемещения, изменения размера, сворачивания
и закрытия. Содержимое следует теме Handler. Размер и положение сохраняются и при восстановлении
ограничиваются безопасным минимумом.

**Сбросить раскладку** возвращает безопасную геометрию главного окна, доков и нативных окон. Команда
не закрывает открытые инструменты и не удаляет проектные данные.

Меню, списки комбобоксов, календари, подсказки и контекстные панели — временные popup, а не окна из
этого справочника. Они закрываются после выбора или клика снаружи и остаются в рабочей области монитора.

## Модальные и обычные окна

| Тип | Поведение |
| --- | --- |
| Обычный инструмент | Может оставаться открытым при работе с основным пространством. Повторная команда выводит существующее окно вперёд. |
| Модальный редактор | Блокирует владельца, пока подготовленное, потенциально разрушительное или контекстное изменение не применено или отменено. |
| Дочерняя модалка | Принадлежит открывшему её окну, поэтому ошибка или подтверждение не прячется за активным родителем. |

Контекстные редакторы восстанавливают геометрию, но не открываются сами после перезапуска: старые
выделение, связь или подготовленный payload уже могут быть недействительны.

Закрытие окна не всегда равно Отмене. Конфигурация отдельно разрешает несохранённые настройки;
редакторы фильтров, синхронизации и отслеживаемой папки отменяют черновик; редакторы схемы и
зависимостей передают закрытие своему владельцу.

## Конфигурация и проект

| Окно | Назначение и закрытие |
| --- | --- |
| **Конфигурация** | Одна сессия разделов Сервер, Репозитории, Проект, Чекин, Общие, Внешний вид, Кэш, Задачи и Maya. При закрытии разрешает неприменённые настройки. |
| **Настройки сервера** | Сразу открывает URL, прокси, тикет, проверку соединения и серверные обновления. |
| **Настройки проекта** | Открывает серверную конфигурацию активного проекта. |
| **Создать проект** · модальное | Собирает и проверяет идентичность, тип и начальную настройку, затем создаёт проект через TACTIC. |
| **Шаблоны проектов (Project Templates)** · дочернее модальное | Открывается через «Управление шаблонами» при создании проекта. Устанавливает ZIP-пакеты на сервер, скачивает установленные архивы и удаляет пакеты после подтверждения, не удаляя существующие проекты. Закрытие возвращает к мастеру создания. |
| **Редактировать проект** · модальное | Меняет только подготовленный проект; закрытие не применяет правки молча. |
| **Параметры чекина** | Сразу открывает параметры чекина, чекаута, именования, передачи, превью и секвенций. |
| **Общие настройки** | Поведение аккаунта, общение, обновления и уведомления. |
| **Сцена Maya** | Возврат фокуса после открытия/сохранения и подготовка Maya. |
| **Пресеты серверов** | Редактирует сохранённые входы на сервер; при открытии создаёт черновик, Отмена возвращает исходное. |

Внешний вид, Кэш и Настройки задач являются страницами Конфигурации, а не отдельными
зарегистрированными нативными окнами.

## Поиск и объекты

| Окно | Назначение |
| --- | --- |
| **Отчёт sObject** | Читаемый отчёт о значениях, связях, задачах и снапшотах выбранного объекта; обновляется при открытии. |
| **Фильтр процессов** · модальное | Выбирает процессы для подготовленного Поиска или боковой панели; Применить возвращает выбор, Отмена — входное состояние. |
| **Быстрые фильтры** · модальное | Создаёт, сортирует и редактирует фильтры одного Search Type в подготовленном контексте. |
| **Редактор колонок** | Выбирает и сортирует колонки в разделе «Редактор колонок» админки. Расширенный режим показывает сохранённые определения TACTIC: «Мастер» выводит компактный список колонок и редактирует по одному нативному элементу TACTIC, а XML меняет точную структуру и пользовательские параметры. |
| **Расширенный поиск** | Строит правила полей, связей, AND/OR и TEL для активной вкладки. |
| **Редактор боковой панели** · раздел админки | Создаёт общие вкладки, ссылки, поиски, скрипты и раскладки с явным применением XML. |
| **Предпросмотр поиска** · модальное | Запускает черновик поиска боковой панели, не меняя настоящие вкладки пользователя. |
| **Добавить SObject** | Создаёт объект подготовленного Search Type из серверных полей; требует свежего контекста и не восстанавливает старый после перезапуска. |
| **Дублировать SObject** | Проверяет имя, связанные данные и параметры перед созданием отдельной копии. |
| **Удалить SObject** · модальное | Показывает объекты, план и зависимости и требует явного подтверждения. |
| **Связать SObjects** | Загружает одну instance-связь схемы и переносит объекты между доступной и связанной панелями. |
| **Редактор базы данных** | Массовое редактирование полей находится в доке, а не отдельном окне. |

## Задачи и планирование

| Окно | Назначение |
| --- | --- |
| **Редактор задач** · модальное | Создаёт или меняет точную подготовленную задачу через поля воркфлоу; Сохранить применяет, Отмена не меняет сервер. |
| **Этапы проекта** | Создаёт и редактирует этапы, используемые представлениями планирования. |
| **Рабочее пространство задач** | Полные Карточки/Список/Таблица/Gantt/Календарь открываются из дока Задач и остаются подготовленными при скрытии. |

Инспектор задач, Календарь, Табель и отчёты являются доками и имеют отдельные статьи.

## Файлы, репозитории и чекин

| Окно | Назначение |
| --- | --- |
| **Редактор имён** | Строит и проверяет переиспользуемые правила именования на подготовленных объектах и файлах. |
| **Создание скриншота** | Снимает, обрезает и проверяет скриншот текущего подготовленного чекина. |
| **Шаблоны сопоставления** | Настраивает правила файлов для Drop Plate и подготовки. |
| **Редактор репозиториев** | Создаёт и меняет корни, платформенные пути и включённое состояние репозиториев. |
| **Синхронизация репозитория** · модальное | Находит файлы для подготовленных объекта и пресета и добавляет передачи в очередь. Отмена прекращает обнаружение, но не удаляет файлы. |
| **Очередь синхронизации** | Показывает передачи, прогресс, конфликты, отмену и повтор. Закрытие не останавливает очередь. |
| **Очередь отправки** | Финальная проверка и исполнение чекинов. Закрытие не отменяет очередь. |
| **Добавить файлы** | Проверяет файлы для ingest/чекина; старый входной контекст после перезапуска не восстанавливается. |
| **Отслеживаемые папки** · модальное | Показывает настроенные локальные наблюдатели и состояние. |
| **Отслеживаемая папка** · модальное | Создаёт или меняет один каталог и его проектные правила; Отмена удаляет только черновик. |

## DCC и скрипты

| Окно | Назначение |
| --- | --- |
| **Редактор скриптов** | Просматривает синхронизированные скрипты, редактирует, запускает локально или в выбранном DCC и показывает настоящий вывод и traceback. |
| **Скриптовый шелф** | Создаёт общие и личные шелфы проекта или вкладки: подписи, хинты, иконки и порядок кнопок. |
| **Триггеры скриптов** | Назначает любое упорядоченное число скриптов на standalone- или помеченные приложением DCC-действия до/после. |
| **Параметры действия DCC** | Показывает поля, объявленные выбранным DCC для подготовленного нативного действия. |
| **TACTIC Handler Server** | Клиенты, возможности, ручные JSON-команды, результаты запросов и диагностика транспорта. |

Инструменты, «Отзывчивость UI» и окно TACTIC Handler Server доступны только администраторам и
супервайзерам. Для остальных пользователей Handler Server продолжает запускаться автоматически.

Окно параметров строится из манифеста выбранного DCC. Оно не меняет общий режим окружения процесса.
DCC-действия всегда адресованы явно выбранному client ID.

## Общение и пользователи

| Окно | Назначение |
| --- | --- |
| **Сообщения** | Диалоги, ответы, пересылка, реакции и вложения; содержимое остаётся подготовленным при скрытии. |
| **Уведомления** | Непрочитанные и недавние уведомления со ссылками на источник. |
| **Лента активности** | Аудируемые события проекта с фильтрами категории, пользователя, даты и непрерывной истории. Открывается кнопкой с часами и обратной стрелкой — историей событий. |
| **Профиль пользователя** | Профиль, сводка проектных задач и разрешённые недельные итоги рабочих часов. |
| **Пользователи** | Каталог с поиском, использующий тот же профиль в режиме списка. |

Счётчики задач в профиле показывают все, завершённые, незавершённые задачи и сроки выбранного пользователя в текущем проекте. Они учитывают **Behave as** статуса в пайплайне задачи: Complete и Approved означают завершение. Без такого соответствия завершёнными считаются только стандартные статусы Complete/Approved. Процент выполнения на эти счётчики не влияет; завершённые задачи не попадают в просроченные и сроки на этой неделе. Нажатие на бадж статуса или процесса открывает задачи пользователя с соответствующим фильтром.

Профиль другого пользователя не заменяет текущий аккаунт в верхней панели. Чат остаётся в Сообщениях,
а Лента активности показывает события аудита, не являющиеся сообщениями. Длинные и многострочные
значения сворачиваются до 80 символов и раскрываются кнопкой внутри карточки события.

## Администрирование

| Окно | Назначение |
| --- | --- |
| **Администрирование** · модальное | Search Types проекта, схема, воркфлоу, пользователи, группы и права в одном явном админском черновике. |
| **Новый Search Type** · модальное | Создаёт или редактирует один Search Type схемы с проверкой и явным сохранением. |
| **Зависимости процессов** · модальное | Редактирует правила графа процессов; закрытие передаётся владельцу для разрешения изменений. |

Окна показывают только данные и действия, разрешённые TACTIC. Подписи проекта, Search Type, процесса,
статуса, группы и роли не переводятся и не переосмысливаются.

## Обслуживание и диагностика

| Окно | Назначение |
| --- | --- |
| **Справка** | Ищет и читает установленные Markdown-статьи на русском или английском. |
| **Журнал отладки** | Полные события, request ID, подробности, команды и traceback с удалёнными секретами. |
| **Отзывчивость UI** | Измеряет остановки UI и время запросов; само окно не оптимизирует приложение. |
| **Ошибка приложения** · модальное | Показывает понятное исключение, подробности и полный traceback; закрытие подтверждает только этот отчёт. |
| **Обновление** | Проверяет и применяет доступное обновление штатным способом. |
| **Создать обновление** | Собирает управляемое обновление для авторизованного сопровождающего. |

Ошибки и Справка при необходимости привязываются к активному модальному владельцу, поэтому не
прячутся за окном, которое их вызвало.

## Если окно потерялось или всё заблокировано

1. Проверьте панель задач и монитор, на котором окно было в прошлый раз.
2. Завершите активный модальный редактор или нативный вопрос DCC до работы с владельцем.
3. Повторите команду: обычный инструмент переиспользует окно и выводит его вперёд.
4. Используйте **Сбросить раскладку** после изменения расположения мониторов.
5. Откройте Журнал отладки, если содержимое не создалось; пустое окно не означает успешную операцию.

## Клавиатура и указатель

- Системные клавиши перемещают, разворачивают и закрывают нативные окна.
- Escape закрывает временный popup; модальный редактор сам решает, можно ли отменить им черновик.
- Правая кнопка переносит общее контекстное меню к текущим указателю и элементу.
- Длинное popup-меню прокручивается внутри ограниченной поверхности с видимой полосой прокрутки.
- Селектор внутри popup заменяет только предыдущий дочерний селектор, не закрывая родительскую панель.

### Cell editor — редактор ячейки

Редактор ячейки открывает одно значение RAW Database в отдельном блокирующем нативном окне. Завершите или отмените правку перед возвращением к владельцу окна.

### Changelist — чейнджлист

Окно чейнджлиста показывает описание выбранного изменения, файлы, shelves и связанные задачи. Оно открывается из дерева чейнджлистов; содержимое относится к выбранному изменению.
