# Док «Очередь отправки»

> Очередь отправки — финальная проверка и исполнение подготовленных чекинов. Док и отдельное окно
> показывают одну очередь, которой владеет приложение.

## Содержимое элемента

Строка хранит целевой sObject, процесс, контекст, файлы, превью, описание, план версии и источник
подготовки. Раскрытие показывает редактируемые файлы и расширенные параметры до загрузки.

Сохранение DCC попадает сюда как подготовка: во время исполнения выбранный клиент сохраняет по
финальному пути, а Handler переносит файл в репозиторий и создаёт снапшот TACTIC.

## Основные элементы

| Элемент | Поведение |
| --- | --- |
| Галка | Выбирает операции для **Отправить всё**. |
| Автоочистка | Включена по умолчанию: удаляет успешные элементы и оставляет ошибки для проверки. Переключатель запоминает ваш выбор. |
| Очистить очередь | Удаляет подготовленные строки после подтверждения, но не исходные файлы. |
| Отправить всё | Выполняет отмеченные корректные элементы по порядку. |
| Меню строки | Редактирует, повторяет, удаляет или показывает точную операцию. |

Применение поля к отмеченным изменяет только текущие отмеченные идентичности. Удалённая строка удалена
полностью: скрытая копия не участвует в последующем расчёте версии.

## Версия и файлы

Версия рассчитывается по текущим серверным снапшотам и операциям, которые ещё остаются в очереди.
Проверьте имя файла, versionless-результат, контекст, репозиторий и превью. Коллизия серверного пути
считается ошибкой и не решается молчаливой перезаписью.

## Исполнение и повтор

1. Раскройте элемент и проверьте цель, контекст, файлы и описание.
2. Для DCC-подготовки проверьте выбранный клиент.
3. Отметьте строки и нажмите **Отправить всё** либо запустите одну.
4. Оставьте ошибочную строку, изучите полное сообщение и исправьте причину.
5. Повторяйте ту же операцию, только когда это безопасно.

## Состояния и ошибки

- Некорректная подготовка не запускается и остаётся редактируемой.
- Нативное сохранение DCC может пройти до ошибки передачи или чекина TACTIC.
- Отмена прекращает ожидающую работу и не выдаёт её за успех.
- Успешная передача не разрешает дубликат пути TACTIC; перед повтором версия обновляется.
- Закрытие дока не отменяет общую очередь приложения.


## Прогресс серверной очереди

Панель показывает весь отправленный пакет и остаётся видимой независимо от выбранной строки.
Подготовка вычисляет контрольные суммы исходных файлов. Загрузка показывает текущий исходный путь
и учитывает только файлы и байты, подтверждённые сервером. Пока не подготовлены манифесты всех проектов,
общий объём передачи неизвестен. Серверный чекин имеет отдельную шкалу и счётчики завершений,
ошибок и отмен: окончание загрузки ещё не означает сохранение снапшотов.
Видны прошедшее время и время без нового прогресса. При ошибке запроса состояния результат остаётся
неподтверждённым; повторяется чтение состояния, а не сам чекин. Прерванную загрузку можно продолжить
кнопкой «Повторить» в том же пакете. После закрытия Handler принятые задачи продолжаются на сервере;
при следующем запуске восстанавливаются результаты существующих пакетов.
Контрольные точки скриптов перед чекином и удалённые строки сохраняются совместно; выход из Handler
сбрасывает отложенные записи. Серверные результаты сохраняются один раз на ответ; строки с ошибками
и проверенная очистка исходников в режиме Move сохраняют прежнее поведение.
Сообщения INFO о запуске и завершении задач в серверной консоли означают обычную работу очереди.

В файловых проектах доступны обычные вкладки поиска объектов Search. Служебные файловые таблицы читаются через штатный файловый API; администратор может просматривать их схему и число записей в Search Types. Интерфейс Perforce-like открывается в доке Commit Queue. Его можно объединять в стек с Search, перемещать или выносить штатными средствами докинга. «Развернуть панель» занимает всю рабочую область; восстановление возвращает раскладку без перезаписи сохранённых пропорций. Восстановленный из кэша проект выбирает файловый интерфейс до обновления с сервера.
