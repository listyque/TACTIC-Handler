# Check-in и очередь отправки

> Инструменты check-in подготавливают файлы, метаданные, имена, превью и назначения репозиториев перед
> отправкой операций в TACTIC.

## Основные элементы

Drop Plate принимает файлы и сопоставляет их с объектами. Редактор имён управляет шаблонами.

Очередь отправки показывает подготовленные операции, параметры, зависимости, прогресс, ошибки,
повтор, отмену и окончательную отправку. Превью добавляются напрямую в выбранную операцию очереди, а
вложения сообщений и заметок остаются в собственных черновиках.

При перетаскивании файлов на объект появляется единая сглаженная область для Publish и Attachment.
Вариант Add Icon доступен, только если каждый перетаскиваемый файл является изображением-превью
TACTIC: JPEG, PNG или TIFF.

Если Save Snapshot или перетаскивание на объект содержит несколько файлов, выберите один групповой
снапшот или отдельные check-in в исходном порядке. Выбор действует только для текущего пакета и не
меняет настройку Drop Plate по умолчанию.

Перетаскивание файлов на дочернюю связь создаёт по одному дочернему серч-объекту на файл, связывает
его с раскрытым родителем, берёт имя без расширения и загружает файл в publish. Новый объект,
снапшот и прямая либо instance-связь сохраняются вместе.

До любой отправки инжест проверяет существующие дочерние объекты выбранного родителя. При совпадении
имён пакет останавливается и предлагает обновить точные найденные объекты, пропустить их, явно
создать дубликаты или отменить операцию.

Пункт «Добавить файлы» сначала открывает пакетный редактор. Пакетный редактор поддерживает проектные
правила инжеста: фильтры файлов, шаблоны путей, дополнительные поля, обновление совпавших объектов,
скрипты проверки и обработки.

Скрипты запускаются в TACTIC и получают path, sobject, parent и snapshot; встроенный быстрый инжест
работает даже без необязательной таблицы правил. Очередь отправки показывает редактор операции
только после выбора элемента.

В пустой очереди вместо недоступных параметров и действий отображается короткая начальная подсказка.
Выбранный объект и превью снапшота объединены в одной сводке.

Необязательная ветка контекста снапшота добавляется или редактируется прямо в этой сводке;
неизменённый базовый процесс не показывается как пользовательский контекст. Расширенные параметры и
превью сгенерированного имени файла раскрываются по запросу, а второстепенные действия с превью и
пакетной отправкой находятся в меню.

Автоочистка остаётся в заголовке очереди. Основная кнопка в футере отправляет все готовые операции;
отправка текущей или только отмеченных операций остаётся в меню.

В списках репозиториев показываются настроенные названия, например General, а внутренние коды вроде
base остаются скрытыми. Режим check-in из пайплайна процесса управляет последовательностями,
папками, наборами файлов и versionless-файлами.

Файлы без расширения используют шаблон сопоставления $FILENAME и сохраняют точное имя при подготовке
в репозитории и расширенном создании снапшота TACTIC; точка в конце и выдуманное расширение FILE не
добавляются. Когда включена автоочистка, Очередь отправки удаляет каждую успешно завершённую
операцию и закрывается после успешного завершения всей видимой очереди.

При ошибке или отмене окно остаётся открытым для проверки и повторного запуска. После успешного
чекина, созданного в текущей сессии, соответствующая ветка процесса обновляется и показывает новый
снапшот, только пока родительский серч-объект остаётся выбран в текущем дереве результатов.

Восстановленные операции очереди и завершения после перехода в другое место не меняют интерфейс.
Существующая строка процесса на месте обновляет состояние раскрытия и количество снапшотов при
публикации обновлённой ветки; повторно открывать дерево не требуется.

Когда чекин аттачмента создаёт для объекта первый снапшот-вложение, дерево результатов добавляет и
раскрывает процесс Attachment, даже если встроенные процессы обычно скрыты; явно заданный фильтр
видимости процессов по-прежнему имеет приоритет.

## Как пользоваться

- Перед запуском операции проверьте целевой объект, процесс, контекст, репозиторий и имена файлов.
- Сохранение сцены в DCC подготавливает данные; check-in выполняет самостоятельное приложение.
- При узкой ширине панели очереди и операции остаются в границах своих частей разделителя; вторичные
  кнопки с подписями превращаются в кнопки-иконки с подсказками и не перекрывают соседнюю панель.
- Окно шаблонов сопоставления удерживает строки внутри своей панели, оставляет место для полосы
  прокрутки и переносит вторичные действия сортировки в меню при узкой ширине.
