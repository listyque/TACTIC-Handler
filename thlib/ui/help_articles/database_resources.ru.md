# Ресурсы БД

Откройте **Configuration → Ресурсы БД** под администратором TACTIC. Здесь настраиваются подключения проектов из `sthpw/db_resource`. Подключение системной базы остаётся в конфигурации сервера.

Нажмите **Новый ресурс**, укажите неизменяемый код, СУБД и параметры подключения, затем **Сохранить подключение**. Поддерживаются PostgreSQL и локальная SQLite. Файл SQLite должен уже существовать в каталоге данных сервера. Сохранённый пароль не отображается: пустое поле нового пароля сохраняет текущий; введённый пароль заменяет его. Для удаления выберите **Удалить сохранённый пароль**.

Укажите имя базы и нажмите **Проверить подключение**. Сначала сохраните изменения подключения. Выбор проекта подставляет имя его базы; **Привязать проект** назначает выбранный ресурс. Целевая база должна уже содержать схему проекта TACTIC. Привязка меняет маршрутизацию следующих запросов: базы не создаются, данные не копируются и не переносятся. **Подключение из конфигурации сервера** снимает переопределение выбранного проекта после проверки подключения по умолчанию. Изменение используемого подключения требует подтверждения. Удалить ресурс со ссылками проектов, в том числе архивных, нельзя.

**Обновить схему** применяет принятые изменения конфигурационной схемы только к базе, привязанной к выбранному ресурсу. PostgreSQL использует транзакционную блокировку; при ошибке изменения этой базы откатываются. Повторное обновление безопасно, данные проекта сохраняются. Общая команда `upgrade`, вызываемая стандартным запуском и обновлением сервера, теперь обрабатывает и зарегистрированные внешние ресурсы, пропуская повторяющиеся подключения. Транзакция действует на одну базу, а не на всю установку. Недоступность внешней базы или отсутствие прав на изменение схемы останавливает обновление: исправьте подключение или права и повторите операцию. Перед обновлением сервера создавайте резервные копии баз.

Apply сохраняет текущую страницу Configuration; Save — все изменённые страницы. Сброс отменяет изменения текущего подключения. При неизвестном результате записи сначала загрузите данные заново. Все операции выполняются сервером и доступны только администратору; ТХ и браузер не подключаются к PostgreSQL напрямую. Удаление подключения не удаляет базу. Создание баз, перенос данных и резервное копирование выполняются отдельно.
