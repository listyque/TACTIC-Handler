# Настройка сервера

> Здесь выбираются адрес TACTIC и пресет подключения, показывается активная учётная запись и
> задаются интервалы общих фоновых запросов.

## Подключение

| Параметр или действие | Что делает |
| --- | --- |
| **Адрес сервера** | HTTP-адрес TACTIC из текущего черновика, который использует кнопка **Проверить**. Смена адреса сама по себе не авторизует пользователя. |
| **Пресет сервера** | Выбирает сохранённый набор адреса, состояния учётной записи, портала и прокси-маршрутизации. |
| **Выполнение запросов** | **Локально**: исходник процедуры отправляется при каждом вызове, установка на сервере не нужна. **Серверный плагин**: запросы запускаются нативной командой TACTIC из версионированного пакета `tactic_handler_queries`. Администраторский сеанс автоматически устанавливает недостающую версию и повторяет вызов, пока воркеры подхватывают пакет. Если модуль всё ещё не виден, перезапустите службу TACTIC через её менеджер: Handler не перезапускает общий сервер через XML-RPC. Если плагин недоступен, только каталог проектов, метаданные проекта и начальное обновление кэша используют прежний путь выполнения скрипта, чтобы вход оставался возможен. Ошибки остальных запросов не скрываются. Режим хранится по адресу сервера для всей установки. Остальные пользовательские скрипты работают локально. |
| **Редактировать пресеты и маршрутизацию** | Открывает редактор серверных пресетов без сохранения текущей страницы. |
| **Текущая учётная запись** | Показывает логин активного тикета либо состояние **Вход не выполнен**. |
| **Проверить** | Проверяет показанные сейчас адрес и маршрутизацию. Не сохраняет черновик и не спрашивает пароль. |
| **Создать тикет** | Применяет страницу сервера и открывает авторизацию TACTIC. Только это действие в настройках сервера запрашивает логин и пароль. |

После входа на другой сервер Handler проверяет, есть ли на нём ранее выбранный
проект. Если его нет, перед загрузкой рабочего пространства выбирается
доступный проект нового сервера.

## Фоновые проверки

| Параметр | Варианты и действие |
| --- | --- |
| **Обновления сервера** | Каждые 5, 10, 30 или 60 секунд. Один пакетный запрос проверяет соединение, обновляет сообщения, реакции, активность и изменения задач и отмечает присутствие текущего пользователя. Для присутствия обновляется одна запись `sthpw/message` на пользователя, а не журнал активности собжекта. Меньший интервал даёт более свежие данные, но увеличивает число запросов и записей присутствия. В меню соединения остаётся ручная команда **Проверить сейчас**. |

## Обновления приложения

В поле **Ключ поиска sObject обновлений** укажите полный search key объекта TACTIC, на который загружаются снапшоты релизов. Пустое поле отключает проверки. Handler проверяет версии после входа и каждые 24 часа работы. В снапшоте должен быть ZIP с четырьмя числами версии в имени (например, `0_5_1_0.zip`). Внутри — содержимое каталога `app` портативной сборки, включая `launch.py` и `thlib/version.json` с той же версией.
Публиковать снапшоты на этом объекте должны только доверенные сопровождающие: при установке выполняется код из ZIP.

При появлении новой версии можно выбрать **Установить обновление** или **Позже**. В окне обновлений также доступны старые снапшоты и локальные предыдущие установки для отката. Перед установкой ZIP загружается и проверяется; затем Handler закрывается, каталог `app` заменяется, локальные настройки и скрипты сохраняются, программа запускается вновь. Если новая версия не дойдёт до первого кадра, установщик вернёт и запустит предыдущую. Автоустановка работает только в портативной сборке: исходный checkout и встроенный Python она не меняет. Новые Python-зависимости устанавливаются отдельно.

Полная история версий открывается через **Меню приложения → Обновление**.
Администратор или супервайзер может открыть генератор релизного архива через
**Ctrl + двойной клик** по текущей версии в этом окне — как в legacy-интерфейсе.
Обычный пользователь может устанавливать опубликованные обновления, но не
создавать релизные архивы.

На вкладке **История изменений** показана полная история установленной версии,
доступная и без соединения с сервером. Записи читаются из `CHANGELOG.md`, который
входит в ZIP обновления. Каждая завершённая правка увеличивает последнюю цифру
версии и получает запись с датой. Генератор архива подставляет текущую версию
и её описание из changelog; повторная сборка того же релиза сохраняет номер.
Для создания архива нужна запись выбранной версии в `CHANGELOG.md`.

## Редактор серверных пресетов

| Поле или действие | Что делает |
| --- | --- |
| **Имя пресета / Добавить пресет** | Создаёт новый черновик пресета с уникальным видимым именем. |
| **Активный пресет** | Помечает пресет, который сейчас использует настройка сервера. Перед удалением выберите другой. |
| **Удалить пресет** | После подтверждения удаляет выбранный неактивный черновик пресета. |
| **Адрес сервера** | HTTP-адрес, сохранённый в этом пресете. |
| **TACTIC TEAM Mode (local repository)** | Для локальной установки TEAM с общим репозиторием TACTIC и Handler. При вводе `http://127.0.0.1:9123` галочка включается автоматически; её можно снять. При включении превью читаются локально, Check-in работает в режиме In-Place, а Check-out — Local. Эти три настройки блокируются на странице параметров Check-in. Перед отправкой файлов проверьте, что оба приложения используют один путь репозитория. |
| **Сохранённая учётная запись** | Доступное только для чтения состояние логина. Авторизация меняется только через **Создать тикет**. |
| **Использовать портал / Имя сайта** | При включении направляет запросы через указанный портал TACTIC. |
| **Использовать прокси / Сервер прокси** | При включении направляет запросы этого пресета через прокси. |
| **Логин прокси / Пароль прокси** | Необязательные данные, используемые только прокси-маршрутом. |
| **Сохранить** | Записывает все черновики пресетов и возвращает их на страницу сервера. |
| **Отмена** | Закрывает редактор, не записывая черновики. |

Сам редактор никогда не спрашивает пароль TACTIC: для входа вернитесь на эту страницу и нажмите
**Создать тикет**.
Если монитор отключён или изменилось его разрешение, окно редактора с сохранённой позицией за пределами экрана автоматически возвращается в видимую область. Пресеты и положение остальных окон не сбрасываются.

При активном режиме TEAM после сохранения настроек репозитория Handler отдельно
спрашивает, нужно ли записать выбранный путь репозитория по умолчанию в общий
серверный параметр TACTIC для этого репозитория. Изменение подтверждает только
администратор или супервайзер TACTIC; папка должна быть доступна серверному процессу. Отмена
оставляет конфиг сервера без изменений. Если пути различаются, файлы In-Place
могут быть не видны в веб-интерфейсе. Если после изменения веб-интерфейс всё
ещё использует старый путь, перезапустите TACTIC.
Позже этот шаг можно повторить кнопкой **Синхронизировать путь** в редакторе
репозиториев, не меняя локальные настройки.

Если проверка не проходит, сначала проверьте схему (`http://` или `https://`), хост и порт, затем
параметры портала и прокси выбранного пресета.


## Обновления от сервера (SSE)

ТХ автоматически переподключается, если открытый SSE-канал закрылся или ответ с обновлениями оборвался; такие сетевые сбои не открывают окно Application error. Каждый сбой SSE записывается в **communication/server-updates** с уровнем **ERROR**, включённым в настройках Debug Log по умолчанию. В деталях — адрес запроса, хост/порт сервера, проект, каналы, HTTP-статус, сетевая причина Qt и номер попытки; ticket и данные авторизации proxy не записываются. При неверном формате ответа сохраняется traceback разбора. Истечение сессии по-прежнему требует входа, отказ в доступе остаётся видимым. Отмена или замена подписки не считается ошибкой.

Выберите **Получение обновлений → Обновления от сервера (SSE)** на странице Server или в меню соединения. Периодический опрос остаётся режимом по умолчанию; интервал показывается только для него. Apply/Save использует штатную конфигурацию, Cancel отменяет неприменённый черновик. Нужен сервер TACTIC Stream с `/admin/server-events`; для другого TACTIC выбирайте опрос. Ошибки не переключают режим скрыто. Ticket, курсоры и подписки передаются в POST-теле, не в URL. Используется настроенный proxy; перенаправления с credentials не выполняются.

Отдельный процесс updates под монитором Stream объединяет native commit-сигналы. Qt асинхронно получает подходящие уведомления каналов/типов, объединяет их за 200 мс и читает обновления одним запросом за раз. Подписываются данные активного Search Type, счётчики задач/заметок/файлов, Task Manager/Inspector и чаты. Закрытый Messages сохраняет уведомления чатов. Activity Feed получает события проекта при открытии или включённых уведомлениях. Проектные записи используют свой проект, сообщения — delivery recipients. При неполных метаданных возможно широкое уведомление типа. Подписка работает по Search Type, не отдельному объекту.

Смена проекта, подписок или режима закрывает старое соединение. На время чекина канал закрывается, после — восстанавливается. Курсоры и черновики остаются у прежних контроллеров. Ошибочные чтения не копятся в очередь; повторные подключения используют задержку и разброс. Авторизация, доступ к проекту и присутствие всё ещё проверяются лёгким запросом раз в 20 секунд. Завершение ТХ останавливает таймеры, запросы и канал.

Feed общий для одного сервера Stream. Внешний SQL вне native-транзакций и exactly-once доставка не поддерживаются; потерянный post-commit сигнал компенсирует повторное подключение или ручное обновление. Буферизация proxy должна быть выключена. Проверяются настоящий Qt HTTP, объединение 100 уведомлений, сервис ТХ против native Stream, регрессии опроса и реальный QML настроек. Production нагрузка Apache/PostgreSQL и portal/proxy подключения этими тестами не подтверждены.


### Исправления после проверки SSE (Stream 0.112.47 / Handler 0.6.0.20)

Оба клиента также подписаны на справочники, Script Shelf/конфигурацию виджетов, скрипты и определения триггеров. Активный поиск учитывает связи и журналы статусов, направленные по проекту штатной записи. Участники нескольких изменённых сообщений объединяются; для вложений чата используются уже захваченные участники message_log, если они известны. Дополнительных чтений БД после commit нет. Каждый новый SSE-канал явно инвалидирует подписанные типы, в том числе при запуске с сохранённым кэшем без journal cursor. Такая начальная синхронизация может перечитать модели при смене подписок; в простое канал молчит. Веб-полка и редактор объединяют обновления каталога во время занятости, сохраняя несохранённые буферы. Остальные ограничения выше остаются в силе.


Обновление каталога веб-полки откладывается при несохранённых изменениях редактора: исходная ревизия сохранения и проверка конфликта остаются прежними. Метаданные pipeline/schema/search type инвалидируют справочный кэш выбранного проекта; config/process также входит в подписку.


### Настройки обновлений и открытые соединения

В Конфигурация → Сервер каждый клиент выбирает периодические проверки или SSE. Для SSE **Задержка объединения обновлений** объединяет полученные события перед одним запросом данных: 100, 200 (по умолчанию), 500 или 1000 мс. Это фиксированное окно, которое не перезапускается каждым событием: непрерывные изменения не могут бесконечно откладывать запрос. Новое значение действует для следующих окон, сохраняя ожидающие запросы. Apply/Save сохраняют настройку; Cancel отменяет неприменённый черновик. Интервал периодических проверок остаётся отдельным.

В веб-конфигурации администратора Stream, Конфигурация → Сервер → Процессы и мониторинг, **Интервал сбора обновлений** задаёт период единого серверного сборщика и проверки его feed каждым веб-воркером: 0,1–2 секунды, по умолчанию 0,5. Сохраните штатный XML и перезапустите backend. Больший интервал объединяет больше транзакций, меньший сокращает задержку. Настройка не меняет heartbeat авторизации/присутствия и не включает сканирование БД. В ТХ число процессов и явный перезапуск доступны в «Администрирование → Сервер ТС»; остальные серверные параметры настраиваются через веб-конфигурацию Stream.

Там же администратор видит **SSE-соединения** всех веб-воркеров: логин, проект, клиент, сетевой адрес, время подключения, PID воркера и подписки на каналы/типы. Несколько строк одного пользователя — отдельные открытые соединения, например вкладки браузера и ТХ. **Обновить соединения** перечитывает список, сохраняя черновик настроек. Дополнительного опроса браузером нет. Обычное отключение отражается за интервал сбора; аварийно завершённый воркер исчезает через 45 секунд. Список доступен только авторизованным администраторам. Тикеты и содержимое запросов не записываются. Прокси может отображаться вместо адреса клиента, если доверенный прокси не настроен. Название клиента — информационная метка, а не подтверждённая идентичность. Периодические клиенты, XML-RPC-запросы и присутствие пользователей в этот список не входят.

Блок опциональной доставки SSE и её настроек в обоих клиентах завершён. Windows WNS и Web Push браузера — отдельные будущие интеграции; неработающих переключателей для них нет. Сохраняются описанные выше ограничения общего локального кэша, внешнего SQL и аварии между commit и публикацией маркера.


Раннее отключение до первого SSE-пакета, включая ошибку отправки заголовков, удаляет подписку на границе ответа. Проверены оба сценария отключения ASGI. Браузер и ТХ явно указывают свою метку соединения; остальные клиенты показываются как неизвестные. Эти метки остаются информационными.

## Выбор транспорта API в ТХ

В ТХ откройте **Настройки → Сервер**, выберите пресет подключения и установите **Транспорт API**:

- **XML-RPC** — значение по умолчанию для старых и новых пресетов. Работает с Legacy TACTIC и TACTIC Stream.
- **JSON (TACTIC Stream)** — использует `/admin/rpc` сервера ТС. Перед включением обновите и перезапустите ТС и ТХ. У Legacy TACTIC этого адреса нет.

**Проверить** проверяет выбранные транспорт, адрес и прокси черновика без сохранения. **Применить** или **Создать тикет** сохраняет выбор в выбранном пресете, переподключается и открывает авторизацию. **Отмена** отбрасывает черновик. В редакторе **Пресеты и маршрутизация** транспорт также выбирается отдельно для каждого пресета; сохранение одного пресета не меняет транспорт другого. Старые пресеты без этого поля продолжают работать через XML-RPC.

Выбор действует на вход, запросы объектов, команды и серверные Python-процедуры. Бинарные данные и даты сохраняют типы SDK. Загрузка файлов и скачивание из репозитория используют прежние HTTP-адреса. **Выполнение запросов: Локально / Серверный плагин** и **Получение обновлений: Периодические проверки / SSE** остаются отдельными настройками.

Ошибка JSON показывается явно: клиент не переключает транспорт автоматически и не повторяет запись. Для подключения к Legacy явно выберите XML-RPC. Оба RPC-пути используют одинаковые серверные права и журнал запросов.

Этот выбор подключения относится к ТХ. Браузер ТС работает со своим сервером через JSON; выбора транспорта для подключения к Legacy в нём нет.


## Вход и возможности клиентов

Help и Debug Log доступны до входа. Enter отправляет только заполненную пару логин/пароль, пока авторизация не выполняется. Handler сохраняет существующие presets сервера, генерацию ticket, proxy и site; изменения presets применяет штатный владелец Configuration. Stream входит на текущий origin браузера и не предоставляет нативную маршрутизацию presets. Пароль очищается при закрытии окна входа.

Обновления Handler используют прежний контроллер релизов: changelog, проверку portable-установки, отмену и подтверждение установки. Для сопровождающих Ctrl + двойной клик по текущей версии открывает создание релиза. Браузер не устанавливает ZIP нативного клиента. Меню подключения и истечение сессии сохраняют штатных владельцев; общая разметка не выдаёт прав и не повторяет запись с неизвестным результатом.

## Процессы и перезапуск сервера

Администратор может открыть **Администрирование → Сервер ТС** в ТХ или ТС.
**Веб-процессы** меняет `services/process_count` для этой установки, а
**Работает веб-процессов** показывает готовые процессы по данным монитора.
Сначала сохраните значение, затем нажмите **Перезапустить ТС** и подтвердите
разрыв соединений. Само сохранение сервер не перезапускает. «Обновить» повторно
считывает настройки; «Отменить изменения» явно отбрасывает черновик. Если
конфигурацию изменил другой администратор, перед перезапуском её нужно перечитать.

Текущий монитор заново запускает свои процессы с сохранёнными настройками;
удалённая оболочка или новый лаунчер из интерфейса не запускаются. Интерфейс
ожидает до 90 секунд, пока именно этот перезапуск завершится, и не отправляет
команду повторно при потере связи. Нужны права администратора и актуальный
TacticMonitor. Явные параметры командной строки сохраняют приоритет. Если меняли
сетевой адрес, откройте новый адрес и подключитесь заново. Закрытие интерфейса
не отменяет уже принятый перезапуск; краткий разрыв затрагивает других клиентов.
Перезапускайте сервер, когда на нём нет критичных операций.
