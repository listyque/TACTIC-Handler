# Очередь отправки

> Commit Queue — финальная проверка и запуск подготовленных Check-in. Само добавление ничего не
> отправляет: выберите операцию, проверьте файлы и назначение, затем запустите нужное действие.

## Панель очереди

| Элемент | Что делает |
| --- | --- |
| **Справка** | Открывает эту статью. |
| **Автоочистка** | Автоматически удаляет каждую успешную операцию. Ошибки и отменённые операции остаются для диагностики или повтора. |
| **Переместить вверх / вниз** | Меняет порядок выполнения выбранной строки. Кнопки появляются, только если операций больше одной. |
| **Очистить завершённые** | Удаляет завершённые строки, не трогая подготовленные, выполняющиеся, ошибочные и отменённые. |
| **Очистить очередь** | После подтверждения удаляет все подготовленные, ошибочные и завершённые операции. Ничего не отправляет. |

Строка очереди показывает галку, назначение, контекст, число файлов, состояние и прогресс. Клик по
строке выбирает её для редактирования, а крестик удаляет только эту операцию. Галка используется
действием **Отправить выбранные** и пакетным редактированием; обычное выделение строки — не то же
самое, что галка.

## Панель файлов

Слева снизу перечислены источники выбранной операции. Крестик удаляет файл только из операции.
Удаление последнего обязательного файла может сделать операцию невалидной, но исходный файл на
диске не удаляется.

## Сводка операции и превью

Сводка показывает целевой объект и состояние снапшота. **Добавить контекст** редактирует только
ветку под базовым процессом. Действия с превью:

| Действие | Результат |
| --- | --- |
| **Сделать снимок экрана** | Открывает Screenshot Maker и прикрепляет результат к этой операции. |
| **Выбрать изображения превью** | Добавляет одно или несколько существующих изображений. |
| **Вставить превью из буфера** | Добавляет текущее изображение из буфера обмена, если оно там есть. |
| **Управлять превью** | Открывает полный список, где можно удалить отдельное изображение. |
| **Очистить превью операции** | Удаляет все вложенные превью из операции, но не с диска. |

При узкой ширине второстепенные действия переезжают в меню с тремя точками, не меняя поведения.

## Основные и расширенные параметры

**Описание** попадёт в метаданные снапшота. Раздел **Расширенные параметры** содержит:

| Поле | Значение |
| --- | --- |
| **Репозиторий** | Репозиторий назначения. В интерфейсе показано название, а внутренний код TACTIC остаётся технической деталью. |
| **Версия** | Явный номер версии. Оставьте пустым или нулём для автоматического назначения. |
| **Метод** | Контракт Preallocate, In-Place, Copy, Move или Upload для этой операции. |
| **Имя файла** | Явное имя назначения. Пустое поле использует правила именования; поле отключается, если именем служит контекст. |
| **Обновить versionless** | Обновляет versionless/latest вместе с нумерованной версией. |
| **Только versionless** | Создаёт только versionless-результат. |
| **Сохранить имя источника** | Оставляет исходные имена вместо сгенерированных. |
| **Использовать контекст как имя** | Получает имя файла из контекста снапшота. |
| **Создать превью** | Создаёт поддерживаемые миниатюры и производные превью. |

При включённом **Применять каждое изменение к отмеченным элементам** любая правка ниже применяется
к текущей операции и всем строкам с галками. Перед редактированием проверьте набор отмеченных строк.

## Предпросмотр именования

Строка имени раскрывается и показывает исходное имя, предполагаемый versioned-путь и
versionless-путь каждого файла. **Редактор именования** меняет шаблоны генерации. Надпись об
ожидании означает, что предпросмотр ещё не рассчитан; это не уже созданный путь.

## Запуск и управление

| Кнопка | Что делает |
| --- | --- |
| **Отправить все** | Запускает все готовые операции в порядке очереди. |
| **Дополнительные действия → Отправить текущую** | Запускает только выделенную строку. |
| **Дополнительные действия → Отправить выбранные** | Запускает готовые строки с галками. |
| **Отмена** | Запрашивает отмену выполняющейся работы. |
| **Повторить** | Заново запускает ошибочную или отменённую операцию после исправления причины. |

Запрос о дубликате приостанавливает подготовку: **Заменить** выбирает совпавший элемент,
**Добавить ещё один** сохраняет отдельный дубликат, а **Игнорировать дубликат** закрывает это
решение. Перед повтором прочитайте ошибку операции: очередь сохраняет полные детали сбоя и не
считает такую строку завершённой.


## Опциональная серверная очередь в Tactic Handler

В очереди чекинов настольного ТХ переключатель **На сервере**
отправляет части файлов и метаданные в TACTIC Stream. По умолчанию он выключен; существующий
клиентский чекин остаётся доступен.

- Чанк содержит до 50 частей или 32 МиБ. Большой файл делится на части по 16 МиБ.
- Один чекин начинается только после получения всех его файлов. Несколько чекинов входят
  в общий пакет; один запрос раз в секунду читает изменения статусов всех активных пакетов.
- Фактические версии и имена рассчитывает штатный серверный naming при выполнении операции.
  Отдельных клиентских naming/start/save/finish RPC для каждой строки в этом режиме нет.
- Работу последовательно выполняют существующие `sthpw/queue`, `Queue` и `JobTask`.
  Нужен включённый **сервис queue** в конфигурации сервера; после обновления сервера следует
  перезапустить монитор. Новый брокер и таблица чейнджлистов не создаются.
- Чекин выполняется от имени отправителя. Права на проект, объект, repository и Python-
  скрипты проверяются повторно при исполнении. Администраторский воркер не повышает права.
  Штатные callbacks, триггеры, откат SQL и файловая история сохраняются. Состояние загрузки
  сохраняется без дублирования всего манифеста чанка в историю Undo.
- При обрыве **Повторить** отправляет исходный пакет с теми же идентификаторами чанков;
  принятые чанки не создают повторных чекинов. Закрытие ТХ оставляет принятую работу на
  сервере; после открытия клиент восстанавливает наблюдение за результатами.
- **Отмена** запрещает новые части и останавливает ещё не запущенные операции. Уже
  выполняющийся чекин завершается. Падение воркера оставляет ошибку для ручной проверки:
  мутации автоматически не повторяются, поскольку внешние эффекты скрипта могут остаться.
- Copy сохраняет исходники. Move удаляет их лишь после подтверждённого сохранения на
  сервере и повторной проверки хеша. Изменившиеся исходники остаются с сообщением об ошибке.
- Подготовка DCC-сцен, snapshots других типов и клиентские repositories используют легаси.
  Предел пакета — 2000 операций / 10 000 файлов. Метаданные multipart ограничены 1 МиБ на
  поле, весь HTTP-запрос — 64 МиБ. Поддержка 100 000 файлов этим изменением не заявляется.

Фиксированные маршруты: `/admin/checkin-queue/submit` — multipart-части и JSON-манифест;
`/admin/checkin-queue/updates` — идентификаторы всех пакетов и курсоры ревизий;
`/admin/checkin-queue/cancel` — идентификатор одного пакета. Нужны ticket и project;
результаты видит только отправитель. Ограничения `api_method_restricted` и
`api_cmd_restricted` сохраняются. Данные незавершённых и ошибочных загрузок остаются во
временном каталоге для проверки; успешные временные файлы удаляются после commit.
Штатные частичные коммиты разных БД и внешние эффекты не покрываются распределённым откатом.

Серверная очередь принимает одну группу больше 1000 файлов в пределах действующего лимита 10 000 файлов на пакет.
Для этого нужен обновлённый сервер; лимит сопоставления в браузере остаётся 1000 файлов.

## Подготовка большого количества файлов в Separate

Separate добавляет выбранные операции одной вставкой в модель очереди и одной записью кэша pending.
В legacy preview нейминга выполняется порциями до 50 операций; одновременно работает одна порция.
Для каждого файла отдельно выполняются штатные правила и callbacks нейминга; результаты между файлами не переиспользуются.
Редактирование строки отменяет её старый ответ. Удаление строки не запускает новые preview-операции для неё; завершение Handler останавливает отправку новых порций.
Обновления preview сохраняются совместно; при закрытии Handler состояние записывается полностью.
Локальная ошибка подготовки относится к своей строке. Серверная ошибка нейминга откатывает всю порцию запроса
штатной транзакцией, включая записи callback; другие порции продолжают работу. Исправьте причину перед повтором.
При фактическом legacy чекине нейминг вычисляется заново: preview не резервирует версию или итоговый путь.
С включённой **Серверной очередью** клиентские preview-запросы virtual snapshot не выполняются.
После обновления перезапустите Handler. Если Server Queries использует опциональный режим plugin, установите соответствующий query-плагин из обновлённого клиента.


## Прогресс серверной очереди

Панель показывает весь отправленный пакет и остаётся видимой независимо от выбранной строки.
Подготовка вычисляет контрольные суммы исходных файлов. Загрузка показывает текущий исходный путь
и учитывает только файлы и байты, подтверждённые сервером. Пока не подготовлены манифесты всех проектов,
общий объём передачи неизвестен. Серверный чекин имеет отдельную шкалу и счётчики завершений,
ошибок и отмен: окончание загрузки ещё не означает сохранение снапшотов.
Видны прошедшее время и время без нового прогресса. При ошибке запроса состояния результат остаётся
неподтверждённым; повторяется чтение состояния, а не сам чекин. Прерванную загрузку можно продолжить
кнопкой «Повторить» в том же пакете. После закрытия Handler принятые задачи продолжаются на сервере;
при следующем запуске восстанавливаются результаты существующих пакетов.
Контрольные точки скриптов перед чекином и удалённые строки сохраняются совместно; выход из Handler
сбрасывает отложенные записи. Серверные результаты сохраняются один раз на ответ; строки с ошибками
и проверенная очистка исходников в режиме Move сохраняют прежнее поведение.
Сообщения INFO о запуске и завершении задач в серверной консоли означают обычную работу очереди.

Ручная очистка свободной очереди также сбрасывает общий прогресс. Кнопка очистки доступна, когда автоочистка уже удалила все строки, а итоговые счётчики ещё видны. Удаление последних завершённых строк тоже скрывает панель прогресса. Сама автоочистка сохраняет итоговые счётчики; активные серверные задачи сохраняют прогресс и состояние восстановления.

Положение горизонтального сплиттера сохраняется после отпускания мыши и восстанавливается при открытии окна или приложения. Сужение окна временно ограничивает ширину панелей, сохраняя выбранное соотношение; при расширении оно восстанавливается. Автоочистка находится отдельной строкой под панелью кнопок. В узкой панели параметров «Отправить всё» отображается значком с подсказкой, чтобы действия отправки оставались видимыми.

## Обновление результатов во время работы очереди

В обычном и серверном режимах прогресс файлов, результаты отдельных операций и ошибки показываются по мере выполнения. Дерево результатов, браузер снапшотов, сводки задач и предпросмотры Search Type обновляются после завершения или остановки всего запущенного набора. Успешные чекины объединяются по объекту и контексту, а клиентский кэш данных сбрасывается один раз для каждого затронутого проекта. Триггеры завершения и результаты API по-прежнему выполняются для каждого сохранённого снапшота.

При отмене обновление подтверждённых результатов происходит после безопасной остановки активной операции. Если следующая операция упала, ранее сохранённые файлы всё равно появляются в результатах. Ошибка запроса состояния сервера обновляет уже подтверждённые сохранения; неизвестные результаты сохраняют состояние восстановления и продолжают опрашиваться без повторного чекина. Очистка исходников в режиме Move входит в завершение.

Автоматический фоновый опрос сервера приостанавливается на время работы очереди, включая обновления активности и уведомлений; после остановки данные догружаются. Опрос состояния очереди продолжает показывать прогресс. Уже отправленный фоновый ответ сохраняется до возобновления, а его курсор кэша записывается только после передачи результата. Выход из аккаунта или смена проекта отбрасывает устаревшие отложенные ответы.

## Поведение versionless

Для чекинов `multi_file`, `dir` и `sequence`, а также групповых операций Drop Plate оба переключателя versionless отключены. В обычной и серверной очередях сохраняется только нумерованный снапшот и его файлы. Для обычного файлового чекина выбранные настройки versionless остаются доступны. Массовая правка отмеченных строк не включает versionless для несовместимой операции. Уже отправленная серверная работа сохраняет исходные параметры.
