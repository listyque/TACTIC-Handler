# Рабочее пространство Perforce-like

**Разделение клиентов:** полный файловый процесс из этой справки относится
к standalone ТХ. ТС предоставляет общее серверное ядро/API и просмотр с
администрированием в браузере. Checkout, локальные правки, shelving, submit,
sync и массовая передача файлов выполняются в ТХ; дублировать этот рабочий
интерфейс в браузере не требуется.


Создайте проект по шаблону **Perforce-like file project**. Режим `file_project` включает отдельный файловый интерфейс в доке Commit Queue. Классические проекты сохраняют Classic Commit Queue и прежний чекин. Смена типа классического проекта не переносит его данные. Обычные Search tabs доступны; системные файловые таблицы читаются через штатный API с правами администратора.

ТХ — рабочий клиент для локальных файлов и передач. ТС предоставляет просмотр и администрирование тех же серверных данных. Браузер не определяет изменения на компьютере пользователя: открытие локальных файлов, Проводник, корзина, Reconcile и большие передачи выполняются в ТХ.

Режим проекта сохраняется при уведомлениях соединения, ping и временной потере связи. Файловый интерфейс меняется или сбрасывается при смене активного проекта, выходе из сессии или переключении сервера; обновление статуса соединения не открывает Classic Commit Queue.

В ТХ круглая кнопка с иконкой колонок рядом с вкладками открывает меню **Вид**; название меню показано в подсказке.

Кнопка «Вид», вкладки и действия панели выровнены по одной горизонтальной оси. Когда вкладки не помещаются, горизонтальная полоса прокрутки занимает отдельную строку под ними.

## Локальные правки и вкладки, следующие за выбором

Новые файлы показываются как Added. Существующие сравниваются с Have, а при отсутствии Have — с опубликованным Head. Добавление регистрирует checkout пакетами без создания blobs и задач загрузки. Ранее загруженные pending-данные сохраняются до явного Revert; добавление других файлов не загружает их содержимое.

Reconcile открывает вкладку результатов с локальными добавлениями, изменениями, удалениями и кандидатами на переименование. Неизменённые файлы не включаются. Проверьте таблицу результатов, выделите нужные изменения и нажмите **Добавить в чейнджлист…**. Диалог позволяет выбрать существующий или создать новый список; содержимое файлов не передаётся.

Вкладка **Files**, следующая за выбором, показывает файлы непосредственно в выбранной папке Depot или Workspace. Выбор файла сохраняет его соседей в таблице и выделяет нужную строку; Ctrl/Shift сохраняют мультивыбор. Большие папки загружаются страницами; выбор файла за пределами первой страницы открывает его страницу с соседями. Нажатие на другой файл уже открытой страницы не перезагружает список. Выбор папки очищает сведения предыдущего файла. Workspace использует локальный кеш Reconcile, а до сканирования — серверный Have. Pending/Submitted и Files с фиксированным источником независимы. **History** следует за выбранным файлом; закреплённая вкладка сохраняет свой файл. У нового неопубликованного файла ещё нет опубликованных ревизий.

Окна выбора changelist для Checkout и выбора shelf открываются модально по центру приложения. Их можно перемещать за заголовок; Escape и Отмена закрывают окно. Кнопки используют общие контролы ТХ.


Files и History используют один общий нижний инспектор: поля метаданных с копированием значений, описание, предпросмотр и прокрутка. Files показывает текущий файл, Have/Head и Checked Out By; History — выбранную опубликованную ревизию и её Integrations. Предпросмотр загружается по запросу именно для выбранной ревизии; выбор файла ничего не загружает на сервер.

## История выбранного файла в ТХ

History показывает путь выбранного файла и сворачиваемый заголовок над компактной таблицей: ревизия, чейнджлист, дата отправки, отправитель, тип, размер и описание. Пиктограммы различают добавление, правку, удаление и перенос. Тип берётся из сохранённых данных, а при их отсутствии показывается расширение; настройки типа файла Perforce не выдумываются. Строки виртуализированы; в узком окне есть горизонтальная прокрутка.

Нижняя панель следует за выбранной ревизией: **Details**, **Integrations**, **Preview**. В сведениях показаны точный путь и ревизия, дата, автор, workspace, действие, чейнджлист и описание. Интеграции показывают записанный источник stream/change/version либо сообщение об отсутствии источника. Предпросмотр запрашивает только выбранную опубликованную ревизию при открытии вкладки: текст, ограниченный бинарный образец или небольшое изображение. При смене ревизии старое содержимое не выдаётся за новое; скрытая History не загружает предпросмотр. Вкладки Labels нет: серверная система меток для файловых проектов пока не реализована.

Сплиттер запоминает высоту отдельно от Files. Работают мышь, клавиатура и Ctrl/Shift; в контекстном меню сохранены сравнение ревизий, Get Revision, сохранение и восстановление. Следящая и закреплённая History сохраняют прежнее поведение выбора файла. Описание и workspace закрытого чейнджлиста не раскрываются посторонним. Текущий API возвращает до 1000 последних ревизий; если история длиннее, показано уведомление. Рабочий экран относится к ТХ; ТС предоставляет те же разрешённые данные и справку без браузерного файлового редактора.

## Редактор стрима и иерархия

Откройте **View → Streams**. Переключатель Дерево/Список меняет представление; вложенность определяется связью **Parent**, независимо от пути стрима в depot. Двойной щелчок или **Редактировать стрим** в контекстном меню открывает редактор. ПКМ по пустому месту — **Новый стрим**, по стриму — **Новый дочерний стрим**. Из узлов Stream Graph открывается тот же редактор. Модальное окно появляется по центру и перемещается за заголовок.

Можно создать mainline без родителя либо development/release под mainline или стримом того же типа. Задаются код, имя, описание, depot и родитель. Код, depot и тип существующего стрима неизменяемы; имя, описание, Parent и защиту настроек владельцем можно редактировать. Сервер запрещает циклы и глубину свыше 255 предков; изменения иерархии сериализуются в пределах depot. У настроек собственная ревизия: Submit файлов не создаёт ложного конфликта редактора. Действуют штатные права depot, защита владельцем/администратором и триггеры; ошибка откатывает правку.

Новая реальная ветка разделяет неизменяемый каталог опубликованных файлов родителя без копирования байтов и перечисления всех файлов. Смена Parent сохраняет опубликованные файлы, базы checkout и исходное происхождение ветки. В графе новая связь Parent отделяется от исходного ветвления; курсоры графа замечают изменение настроек.

Дерево загружает метаданные по 200 стримов, удерживая до 2000. Фильтр работает по загруженным записям; ещё не загруженный родитель указан в колонке Parent. Редактор предлагает до 1000 записей и позволяет ввести иной код родителя вручную. Содержимое файлов при этом не перечисляется.

**Граница совместимости с P4:** mainline/development/release сейчас описывают реальные ветки и родительскую иерархию. Автоматических политик merge-down/copy-up пока нет. Virtual/task/sparse, наследуемые Paths/Remapped/Ignored, преобразование ParentView/типа и подсказки необходимости merge/copy ещё не реализованы. Сервер явно отклоняет Virtual: такой стрим должен фильтровать реального предка и отправлять изменения в него, а не создавать независимую копию ветки. Ограничение указано в редакторе; неработающих переключателей для него нет. В браузере ТС остаются просмотр и администрирование.

Документация: [спецификация стрима Perforce](https://help.perforce.com/helix-core/server-apps/p4v/current/Content/P4V/streams.create.html), [virtual](https://help.perforce.com/helix-core/server-apps/p4v/current/Content/P4V/streams.virtual.html), [правила путей](https://help.perforce.com/helix-core/server-apps/p4v/current/Content/P4V/streams.views.html).

## Деревья и вкладки

Слева переключаются **Depot** и **Workspace**. Дети директорий загружаются ограниченными страницами только при раскрытии. Workspace показывает локальный кэш после Reconcile, включая неотслеживаемые файлы и пустые папки, либо серверный Have до локального сканирования. Reconcile обновляет состояние в worker.

Справа через **View** открываются Files, Pending, Submitted, History, Shelved, Reverted, Conflicts и Transfers. Создавайте несколько вкладок с независимыми настройками, переименовывайте, закрывайте и меняйте порядок. Выбор папки обновляет следящую Files, сохраняя Pending/Submitted. Вкладка с фиксированным источником сохраняет свой фильтр. History следует за выбранным файлом или закрепляется. Несохранённое описание нужно сохранить либо явно отменить перед переходом.

Workspace, номер чейнджлиста и контекст операции видны постоянно. Команды находятся в **Actions**, **Workspace actions**, **Tools**, контекстных меню и явных кнопках. При узком окне доступны меню и горизонтальная прокрутка. Штатные доки позволяют перемещать, отделять, разворачивать и восстанавливать панель.

### Компоновка ТХ и сведения о чейнджлисте

Правая рабочая область начинается у верхней границы панели. Выбор workspace,
деревья Depot/Workspace и Actions/Tools находятся слева; независимые вкладки View —
справа. Плюс создаёт чейнджлист. Второстепенные команды доступны в меню и по ПКМ,
без повторяющихся панелей кнопок.

Один клик выделяет чейнджлист, стрелка раскрывает файлы. Двойной щелчок
открывает окно просмотра содержимого, описанное ниже.

Высота **Лога** меняется горизонтальным сплиттером над ним. Крестик в шапке или
**Вид → Скрыть лог** скрывают панель. Вернуть её можно через **Вид → Показать лог**
или кнопку терминала в футере. Высота и видимость сохраняются после повторного
открытия панели и перезапуска ТХ. Скрытие не удаляет записи. Компактный футер
показывает workspace и выделение в покое, а во время операции — этап, счётчики
и прогресс. Эта рабочая компоновка относится к ТХ; в ТС остаётся отдельный
интерфейс просмотра и администрирования.

### Просмотр содержимого чейнджлиста

Двойной щелчок или **Просмотр чейнджлиста** в контекстном меню открывает отдельное
нативное окно. Сверху показаны состояние, workspace, дата создания, владелец,
доступ и stream, затем описание и сворачиваемые таблицы **Файлы**, **Файлы в shelf**
и **Задачи**. Shelf выбирается по своему номеру. Для файлов видны имя, папка,
состояние разрешения конфликтов, расширение и действие; для связанных задач
менеджера задач — код, доступные статус и описание. Закрытые сведения
чейнджлиста доступны только владельцу и администраторам.

Открытие выполняет один ограниченный запрос штатного API. В странице до 200 файлов;
следующие страницы привязаны к ревизии списка. Обновление возвращает первую страницу.
Если список изменён другим клиентом, сначала обновите окно. Таблицы используют
штатные полосы прокрутки, включая горизонтальную в узком окне. Окно сохраняет
идентичность открытого чейнджлиста. **Правка** включает редактирование описания
собственного pending-чейнджлиста; **Сохранить** использует штатный API.
Чужие, submitted и shelved списки доступны только для просмотра. Закрытие
отбрасывает несохранённый текст. Submit, Shelve и Revert доступны в меню футера.

### Refresh и количество запросов

ТХ получает один ограниченный `workspace_snapshot` при Refresh и при обновлении
после обычных файловых операций. Метаданные, задачи, страницы чейнджлистов,
Head/Have и владельцы checkout читаются общей штатной командой. Страница
выбранного чейнджлиста используется и в раскрытой строке. В ответ входят до 32
страниц раскрытых чейнджлистов и 16 страниц директорий. Дальнейшие страницы
дерева и отдельные выделения вне страницы при необходимости читаются ограниченными
запросами. Snapshot не создаёт чейнджлисты, не сканирует всё депо и не загружает
файлы. Инспектор ТС объединяет начальные метаданные тем же API пакетного чтения. Инспектор файла ТХ запрашивает подробности и preview только при видимой вкладке Files.

Кэш записей живёт только внутри запроса чтения. Проверки прав проекта, depot и
workspace сохраняются; следующий запрос читает актуальные записи и права.
Внутри команды остаются чтения отдельных таблиц, авторизации и схемы: один
сетевой запрос не означает один SQL.

Чейнджлисты сортируются по номеру, новые сверху. Фильтр состояния применяется
до пагинации; остальные фильтры видимости заполняют страницу ограниченным
просмотром и возвращают курсор продолжения. Пустые pending-чейнджлисты остаются
видимыми. При передаче владельца обновляется индекс, используемый видом «Мои».
Повтор Create с тем же `request_id` возвращает тот же чейнджлист; изменение данных
под этим id отклоняется. Существующие пустые записи сохраняются для явного
просмотра и удаления.

Детали и Preview читаются одним запросом инспектора файла. При открытии вкладки
чейнджлистов список и файлы выбранного чейнджлиста читаются пакетом. Reconcile
проверяет исходники переименований штатными пакетами до 1000 путей. История
читает ограниченные группы индексированных записей и возвращает только цепочку
предыдущих версий выбранного файла, проверяя опубликованный root каждой версии.
Метаданные схемы и маршрутизации проекта переиспользуются внутри запроса;
штатные структурные записи и откат сбрасывают этот кэш.

Запрос статуса передачи не перезагружает workspace. При неизменном прогрессе
интервал опроса растёт максимум до двух секунд, при изменении — сбрасывается.
Завершение задачи без промежуточного прогресса поэтому может отобразиться
на один интервал позже. Ошибки, таймауты и журналы восстановления сохранены.

Подтверждение в ТХ показывает название действия и отдельно поясняет его эффект.
Кнопка «Отмена» и Escape закрывают диалог без выполнения; кнопка действия
подтверждает его один раз. По умолчанию откат чейнджлиста сохраняет локальные файлы.
Браузерный интерфейс ТС остаётся режимом просмотра этих данных и не показывает
этот диалог изменения файлов.

## Выделение и файлы

Один клик выделяет; двойной открывает файл или историю. Ctrl переключает выделение, Shift выбирает диапазон, стрелки и Shift+стрелки перемещают/расширяют его. ПКМ сохраняет уже выбранную группу. Ctrl+A выбирает загруженные строки, Escape снимает выделение. Оно сохраняется при обновлении, перелистывании и смене вкладки, а новый рабочий контекст очищает прежнюю группу.

Явное выделение ограничено 1000 элементами. **Выбрать все подходящие файлы на сервере** / Ctrl+Shift+A создаёт личную зафиксированную серверную выборку, без загрузки миллионов строк на клиент. ТХ потоково экспортирует её как JSON-lines manifest. Операции checkout/move/delete над всей выборкой относятся к этапу масштабирования; токен не превращается молча в операцию только над видимыми строками.

Меню файла содержит обычный/эксклюзивный checkout, историю, sync, локальное сравнение, серверное переименование, перенос, отмену и копирование путей. Выбор цели предлагает свои pending-чейнджлисты текущего workspace либо явное создание нового. Read-only mappings, чужой exclusive checkout и несовместимые streams объясняют недоступные команды. Окончательные проверки всегда выполняет сервер.

Получение выбранных файлов, поддерева папки и всего workspace — разные операции. Sync защищает изменённые и неотслеживаемые локальные данные, Have обновляется после подтверждённой записи. Встроенный diff локального файла с Head поддерживает UTF-8 до 256 КиБ; для больших/бинарных файлов сохраните ревизию и сравните во внешней программе. Серверное переименование сохраняет историю версий и не переименовывает локальную копию скрытно.

Настраивайте ширину, порядок и видимость колонок. Have/Head и держатели checkout читаются ограниченным штатным запросом. Локальное состояние берётся из кэша и проверки файла; содержимое подтверждает Reconcile. Фильтр и сортировка относятся к загруженным строкам. Адрес, Назад/Вперёд/Родитель и **Показать в другом дереве** находят файл без перебора большого каталога. Такая ветвь сначала показывает только разрешённую цепочку предков; сверните и раскройте её для просмотра соседей.

## Чейнджлисты и перетаскивание

У каждого списка есть уникальный номер проекта, описание, владелец, workspace/stream, состояние, количество файлов/байтов и конфликтов. Раскрывайте файлы и дочерние shelves. Фильтруйте мои списки, текущий workspace, stream или все доступные. Чужие опубликованные версии и shelves доступны для чтения согласно правам depot; чужой private pending просматривает только администратор. Редактирование требует владения и текущего workspace.

Переход по номеру открывает независимую вкладку. Копируйте номер или ссылку на просмотр в ТС. Переносите группу между своими pending-списками; локальные файлы Workspace/Files регистрируют пути в выбранной цели без передачи содержимого. Shelf при перетаскивании начинает unshelve. Наведение раскрывает допустимую цель, края прокручивают список, Escape отменяет жест. Перед изменением сервер проверяет права и ревизии обоих списков.

Файлы и папки из активного workspace можно перетащить на свой pending-чейнджлист: добавление начинается без подтверждения и сохраняет относительные пути. Файлы вне workspace отклоняются сообщением с одной кнопкой OK. Смешанный набор корней внутри/вне workspace отклоняется целиком до серверных запросов, загрузки и копирования. Обход и локальное сравнение идут в worker; mappings, права и ревизии проверяются штатным API.

## Удаление и публикация

- **Revert / Откатить** находится в основном меню файла и доступен для своих открытых файлов активного workspace, включая группу. Диалог опций открывается также для всего чейнджлиста. По умолчанию локальные файлы сохраняются. **Delete files not in depot / Удалить файлы вне depot** после успешного штатного серверного отката перемещает в Корзину только новые добавления, отсутствующие в опубликованном стриме. Файлы, уже существующие в depot, и файлы с историей переименования сохраняются. Перед удалением повторно проверяются Head, другие checkout, mappings и локальный fingerprint; изменённые или недоступные файлы остаются с предупреждением. Большой changelist читается страницами, связанные стороны rename откатываются вместе. Удаление выбранных правок из changelist остаётся отдельной операцией с сохранением локальных файлов.
- Пометка удаления из depot создаёт правку в выбранном pending-списке. Её публикует Submit; удаление pending-правки отменяет пометку.
- Перемещение локальных копий в корзину затрагивает только компьютер. Серверная история сохраняется, требуется подтверждение.
- **Удалить чейнджлист / shelf…** доступно для одного или нескольких выбранных заголовков (выделение Ctrl/Shift или клавиша Delete). Подтверждение показывает номера. Пустые pending-списки и свои полки удаляются вместе одной штатной транзакцией: конфликт ревизии, запрет доступа или ошибка триггера откатывают весь набор. Локальные файлы всегда сохраняются. Из непустого pending-списка сначала перенесите файлы либо выполните Revert. Пользовательское удаление не запускает физический GC.
- **Отменить неизменённые файлы** в контекстном меню чейнджлиста сравнивает весь свой pending-чейнджлист, включая строки, не загруженные в UI. Команда меню файлов обрабатывает только выделенные пути. Обе сравнивают хэш текущего локального файла с исходной ревизией checkout. Правки, добавления, отсутствующие файлы, удаления, переименования и файлы вне mappings остаются. Байты не загружаются на сервер; локальные файлы не удаляются и не перезаписываются. Отсутствие совпадений — информационная запись в логе.
- Проверка идёт в фоне с прогрессом и отменой, страницами до 1000 файлов и временным списком кандидатов на диске. Перед снятием checkout кандидаты проверяются повторно. До 1000 совпадений обрабатываются одной штатной командой, больше — существующей службой files в одной атомарной операции. Сохраняются права, проверки ревизий и триггеры; поздняя ошибка откатывает весь Revert. Чейнджлист остаётся pending, даже если стал пустым. В браузере ТС локальное сравнение недоступно.
- В History выберите неудалённую опубликованную ревизию и восстановление в чейнджлисте. Создаётся новая версия со ссылкой на существующие неизменяемые данные. Правку, уже существующую в цели, сначала нужно перенести/отменить. Ошибка штатного триггера откатывает восстановление целиком.

После Reconcile выберите изменения и нажмите **Добавить в чейнджлист…**: можно выбрать существующий или создать новый pending-чейнджлист. Добавление путей, checkout и Reconcile передают только метаданные. Содержимое остаётся локально до подтверждённого Submit или Shelve. Пропавшие файлы предлагаются как удаления, но не удаляются из depot автоматически. Submit атомарно публикует весь список через штатные права и триггеры.

## Журнал операций

Нижний **Log** показывает время, операцию и результат, а при необходимости — путь
файла. Высота меняется сплиттером; в шапке доступны скрытие, копирование и очистка; **Debug Log** открывает
полную диагностику по запросу. Панель хранит до 1000 итогов операций в памяти,
а не отдельную запись на каждый файл или обновление прогресса. Смена проекта
или выход из сессии очищают журнал этого рабочего пространства.

Изменённый или неотслеживаемый локальный файл останавливает sync обычным результатом
`blocked`. Файл не перезаписывается, исключение и traceback для этого состояния
не создаются. Сохраните свои изменения или подготовьте их к публикации, затем
повторите/продолжите ту же задачу передачи. Неожиданный сбой сохраняет полный
traceback в Debug Log; окно исключения автоматически не открывается. Журнал ТС
отражает просмотр и администрирование серверных данных; изменения файлов на
компьютере определяет ТХ.

Остановленное скачивание теперь фиксируется на сервере как `blocked`, в том числе при конфликте с локальной правкой и восстанавливаемой ошибке передачи. Повтор той же выборки продолжает её зафиксированную задачу. Запрос другого файла, папки или ревизии в том же workspace и локальном корне атомарно заменяет остановленную задачу, сохраняя локальные правки, частичные файлы и подтверждённый Have. Выполняющаяся загрузка и задача с другим локальным корнем автоматически не отменяются. ТС показывает остановленную задачу в Transfers и позволяет отменить её. Задачу, оставленную активной старым клиентом, аварийно завершённым процессом или полной потерей связи, может потребоваться отменить в Transfers перед сменой выборки.

## Get Latest и получение ревизий

Правой кнопкой выберите файл, выделенные файлы, папку на любой глубине, stream,
depot или workspace. **Get latest** обновляет только выбранную область.
**Получить ревизию…** позволяет выбрать latest, номер ревизии каждого файла,
номер опубликованного чейнджлиста, ревизию стрима либо состояние на дату / время.
В истории можно получить выбранную ревизию. Для папок и корней учитываются
вложенные mappings и исключения; локальные копии и Have соседних стримов сохраняются.

Ревизия файла №N берётся отдельно для каждого пути. Если такой ревизии нет,
файл и Have не меняются, в нижнем журнале появляется предупреждение.
Чейнджлист №N задаёт всё опубликованное им состояние, включая удаление ранее
полученных файлов, отсутствующих в этом состоянии. Номера чейнджлистов и ревизий
стрима относятся к конкретному стриму: при нескольких стримах выбирайте его
дерево или папку. Дата ISO допускает часовой пояс; без него используется UTC.
Дата без времени включает весь день по UTC. Новые публикации хранят время до микросекунд.

**Принудительно перезаписать локальные файлы** по умолчанию выключено. Force
восстанавливает изменённые и отсутствующие копии даже при совпадающем Have,
а также удаляет ранее полученные файлы, которых нет в выбранном состоянии.
Сначала сохраните локальные изменения. Без Force изменённый / неучтённый файл
останавливает sync обычным результатом blocked. Включение Force перезапускает
заблокированную передачу только той же области; другую активную выборку нужно
сначала завершить или отменить. Manifest закреплён на время передачи; Have
подтверждается после записи и проверки файлов.

Старые проекты требуют пакетного возобновляемого обновления индекса ревизий
администратором. ТХ выполняет его перед первым историческим запросом и показывает
прогресс; обычный пользователь обращается к администратору. Classic не меняется.
ТС использует общий API просмотра истории и SDK; desktop sync остаётся в ТХ,
поскольку браузер не управляет локальным workspace.

## Перетаскивание папок Depot в чейнджлист

Перетащите файл Depot, папку на любой глубине или стрим в свой ожидающий
чейнджлист того же стрима. Сервер откроет опубликованные файлы для обычного
checkout с сохранением путей. Папки Depot не перемещаются, байты файлов при этом
не скачиваются и не загружаются. Содержимое берётся на неизменяемой базовой
ревизии целевого чейнджлиста; для новых публикаций сначала выполните rebase
старого чейнджлиста. Папки Workspace разрешаются через mappings этого чейнджлиста.
Исключённые и unmapped пути пропускаются; read-only mapping или чужой exclusive
checkout отклоняет всю операцию. Пересекающиеся папки и отдельно выделенные
файлы не дублируются. Если опубликованных доступных файлов нет, в журнале
операций появляется понятная ошибка.

Клиент отправляет до 1000 выделенных корней, не разворачивая на клиенте весь
список потомков. Штатный серверный checkout обходит их порциями до 1000 путей,
сохраняя одну транзакцию: поздняя ошибка блокировки или триггера откатывает и
предыдущие порции. После завершения показывается число открытых файлов.
Перетаскивание из Explorer регистрирует пути workspace без копирования и загрузки содержимого.
В администрировании ТС используется та же операция с метаданными; браузер не
читает и не обнаруживает содержимое файлов desktop workspace.

## Показать в Проводнике до sync

**Show in Explorer / Показать в Проводнике** доступно для mapped-файла в
чейнджлисте, даже если локальной копии ещё нет. Существующий файл выделяется
в Проводнике. Для отсутствующей копии ТХ открывает ближайшую существующую
родительскую папку внутри настроенного workspace и пишет информационное
сообщение в нижний журнал с исходным путём файла. Папки не создаются, байты
не скачиваются. Если самого локального корня нет или он не выбран, Проводник
не запускается: выберите корень или выполните Get Latest согласно сообщению.

Путь разрешается по выбранному файлу и workspace, в том числе когда справа
открыт локальный вид Files, а файл выбран в чейнджлисте. Обычные открытие /
удаление также сообщают об отсутствии локальной копии штатным исходом:
редактор не запускается, попытки перемещения в корзину нет. Неожиданные ошибки
запуска / транспорта сохраняют полный диагностический Debug Log.
Браузерный ТС не запускает desktop-Проводник и не проверяет локальные папки;
там остаются копирование пути и Reveal in other tree.

## Восстановление и ограничения

Stop waiting сохраняет задачу и журнал; resume использует тот же корень. Cancel серверной загрузки восстанавливает исходный черновик. Потерянный ответ Submit/Have сначала проверяется, публикация не повторяется вслепую. Изменённые исходники требуют отмены и новой передачи. Включите серверный сервис `files` и явно перезапустите после смены сервисов: сохранение конфигурации сервер не перезапускает. Только `file_project_busy` повторяется с ограниченной задержкой; права, триггеры и контрольные суммы не повторяются вслепую.

История и загруженная ветвь списка ограничены 1000 записями, preview — 256 КиБ. Серверные выборки читаются страницами. Полные редакторы жизненного цикла, пофайловый учёт передач, операции над всей выборкой и проверка миллионов файлов/ТБ остаются в полном плане из трёх этапов. Исходные тесты не подтверждают физический миллионный/TB прогон или установку EXE/Electron. Предупреждение Property при завершении Python 3.14/PySide6 остаётся зарегистрированным вопросом runtime. Установка/backup описаны в `FILE_PROJECT_DELIVERY.ru.md`; сохраняйте базы и закрытое blob-хранилище совместно.

## Работа с файлами и инспектор Files

Внизу Files находятся независимые вкладки **Details**, **Checked Out By** и
**Preview**. Details показывает пути depot/workspace, выбранную ревизию, Have и
Head, размер, автора и опубликованный чейнджлист. ТХ также проверяет локальный
путь и дату изменения. Checked Out By показывает владельца checkout, workspace,
номер чейнджлиста и обычный/эксклюзивный режим. Preview загружает только выбранный
файл: до 256 КиБ текста, небольшие поддерживаемые изображения либо метаданные и
короткий hex для двоичного файла. ТС не читает файловую систему рабочего компьютера.
Переключение инспектора не заменяет Pending или Submitted.

В Windows фоновое наблюдение сбрасывает актуальность локальных признаков.
**Reconcile** проверяет содержимое в отменяемом worker; отмена сохраняет предыдущий
полный индекс. Корневой `.tacticignore` поддерживает шаблоны, комментарии и
исключения `!`. Read-only и исключённые mappings показываются явно. Однозначная
пара добавленного/пропавшего файла с одинаковым содержимым предлагается как rename;
неоднозначные совпадения остаются add/delete. Выберите изменения и команду
**Добавить в чейнджлист…**, затем существующую или новую pending-цель.
Это регистрирует только метаданные. Submit/Shelve проверяют и загружают актуальное
локальное содержимое после подтверждения. При остановке подготовки серверные правки могут остаться pending;
Resume продолжает ту же задачу/outbox. Атомарная граница публикации — submit.

Shelve доступен для всего чейнджлиста и выбранных файлов. Можно заменить или
удалить выбранные файлы shelf: номер сохраняется, прежнее содержимое архивируется.
Сравнение pending/shelf включает файлы, которые есть только на одной стороне.
Перед submit, shelving и интеграцией просмотрите точные страницы preview;
изменившаяся ревизия отменяет прежнее согласование. Незагруженные новые файлы и
незавершённые конфликты блокируют submit. **Shelve с последующим revert** сначала
сохраняет shelf и откатывает серверные pending-правки; локальные файлы остаются.
Unshelve копирует shelf в pending-цель и может потребовать разрешения конфликтов.
Передача владения — отдельное действие: владелец указывает логин, получатель
явно принимает чейнджлист в свой workspace. Права стрима, mappings и locks
проверяются сервером. Номер и ссылку можно скопировать из меню чейнджлиста;
это не выдаёт получателю дополнительных прав.

Конфликты показывают реальные Base/Ours/Theirs. Явно выбранные пути разрешаются
через Ours/Theirs или вручную объединённый файл; обе стороны rename обрабатываются
вместе. До завершения интеграции разрешение можно отменить во вкладке Resolved.
История содержит чейнджлист, автора, время, действие и описание. ТХ сравнивает
локальный файл с Have/Head, две опубликованные ревизии, pending/shelf и стороны
конфликта. Для небольшого текста доступен встроенный diff; двоичные/большие файлы
можно передать явно выбранному установленному приложению. Серверные копии
проверяются и остаются в cache workspace для внешних viewers; автоматический
retention этих копий пока не принят.

Transfers показывает состояния файлов и полученные байты страницами. Имена и
checkout из upload-manifest видны до передачи содержимого. Очистка завершённых
задач очищает завершённый общий прогресс. Скорость/ETA появляются после замера;
verify/staging показывают счётчики своей фазы. Во время записи в ТХ доступны
представления чтения. Потерянный ответ submit сверяется с состоянием прежнего
чейнджлиста до повторной публикации. Полная проверка восстановления после
рестарта/потери сети и физические миллионы файлов/терабайты остаются в полном
чеклисте трёх этапов. Classic сохраняет существующий интерфейс и работу.

## Редактирование и Submit changelist

ПКМ на пустом месте Pending создаёт пронумерованный changelist. В ТХ перетащите
в него файлы или папки Depot: отсутствующие mapped-копии скачаются из базовой
ревизии changelist, существующие локальные правки сохранятся. Drop из Проводника
подготавливает уже существующие файлы активного workspace без подтверждения и копирования. Двойной щелчок по
pending-файлу открывает его редактор. Отметки локальных правок видны также в
раскрытом changelist. Вкладки закрываются крестиком и открываются из View.

Submit и Shelve проверяют открытые локальные файлы перед review без загрузки.
Отмена review не передаёт байты. После подтверждения загружаются только проверенные
изменённые файлы, затем выполняется публикация или shelving. Посторонние файлы
workspace не добавляются. Если содержимое или ревизия списка изменились после
review, нужна повторная проверка. При отсутствии копии появляется сообщение в Log.
Прерванная подтверждённая передача сохраняет журнал для явного возобновления.
ТС предоставляет просмотр и администрирование; файловые операции выполняются в ТХ.

### Окно Submit

**Submit** открывает модальное окно по центру; его можно двигать за заголовок.
Сверху редактируется описание. В первом списке отметьте файлы для публикации;
во втором показаны связанные shelf с их собственными номерами чейнджлистов.
Shelf остаются отдельными снимками и сохраняются после Submit; этот список служит
для просмотра. Файлы, shelf и задачи загружаются страницами. «Выбрать всё» относится
ко всему чейнджлисту, а не только к странице; допускается до 1000 явных исключений.
Неотмеченные файлы атомарно переносятся в новый pending-чейнджлист при публикации;
их локальное содержимое не загружается и не удаляется.

Параметры позволяют запретить Submit файлов, изменённых после разрешения конфликтов,
снова открыть опубликованные файлы для редактирования и ограничить сведения о
чейнджлисте владельцем и администраторами. Ограничение касается описания, состава
и связанных задач; доступ к опубликованным файлам определяется правами depot.
Для неизменённых файлов можно создать новую ревизию, отменить checkout или оставить
их в pending. Если после отбора нечего публиковать, команда завершается ошибкой
без удаления и переноса файлов.

Выберите существующие задачи **менеджера задач** (до 100) и статус после Submit.
Список статусов берётся из настроенных workflow и содержит только разрешённые
общие статусы выбранных задач. «Не менять статус» сохраняет только связи.
Связи записываются в сведения чейнджлиста. Статусы меняются штатными командами задач
после успешной публикации файлов. Если задачу успели изменить или её обновление
не удалось, файлы остаются опубликованными, а в Log появляется сообщение.
У опубликованного чейнджлиста есть **Обновить статусы связанных задач** для повтора;
параллельные изменения задач не перезаписываются молча.

**Применить** сохраняет описание, ограничение доступа, связи и выбранные статусы
задач, оставляя окно открытым; **Сохранить** делает то же и закрывает окно.
Эти кнопки не загружают содержимое файлов и не меняют статусы задач.
Выбор файлов, политика неизменённых файлов, повторный checkout и защита разрешённых
конфликтов действуют для текущей попытки Submit. **Отмена** закрывает окно без
публикации; уже применённые сведения остаются сохранёнными. Только подтверждённый
Submit загружает выбранные новые/изменённые файлы, затем атомарно публикует их
и создаёт pending-чейнджлист для оставшихся/повторно открытых файлов.
Отсутствующие локальные копии нужно восстановить до review. Classic и браузерный
интерфейс просмотра не получают этот рабочий процесс standalone-клиента.

## Серверные выборки и настройка workspace

Команды Selected server query ставят зафиксированную выборку в серверную очередь:
обычный/эксклюзивный checkout, перенос, выбранный revert или mark-delete. Прогресс
Applying предшествует COMMIT всей транзакции; ошибка или Cancel откатывает пакет.
Stop waiting оставляет серверную задачу. Transfers позволяет обновить статус,
отменить задачу или продолжить ожидание, не загружая полный список путей. Длинная
запись SQLite сериализует записи проекта; физическая скорость миллионов файлов/ТБ
пока не подтверждена.

Workspace setup редактирует mappings, исключения и разрешение записи строками;
доступен Technical JSON. Preview показывает соответствие примерного depot-пути.
Cancel возвращает активный корень и настройки workspace. При переключении pending
и серверные задачи остаются в прежнем workspace. Проверка свободного места при
настройке не резервирует место для будущего download.


Раскрытие changelist читает его текущую серверную ревизию и обновляет сведения в строке. Следующие страницы остаются привязаны к этой ревизии: если другой клиент изменил changelist, обновите список перед продолжением. Изменение файлов, checkout и submit по-прежнему проверяют ожидаемую ревизию. Выбор папки Depot сохраняет независимые Pending/Submitted; чтение дерева в ТХ не включает статус выполняющейся передачи файлов.


Перетаскивание локальных строк Workspace/Files или файлов Проводника, уже находящихся в активном workspace, без подтверждения регистрирует пути в выбранном pending-чейнджлисте без загрузки содержимого. Папки обходятся рекурсивно в worker, пересекающиеся корни не дублируют файлы. Mappings, исключения и права depot сохраняются. Внешние файлы Проводника в workspace не копируются. Внутренние переносы pending-файлов, checkout из Depot и работа с shelf сохраняют подтверждение/review. Локальные операции остаются в ТХ; ТС предоставляет серверный просмотр и администрирование.


## Полное выделение и передача чейнджлиста

Галочки файлов начинают файловое выделение без ранее выбранного заголовка
чейнджлиста. Ctrl позволяет явно смешать объекты; несовместимые команды в таком
случае поясняют запрет. Файловые команды проверяют всё выделение. Папки, чужие чейнджлисты, mappings
только для чтения, отсутствие записи в depot и конфликтующие checkout показывают
причину недоступности команды. Эти подсказки не заменяют серверные проверки
прав, ревизии и блокировок в момент выполнения.

При перетаскивании видны действие и число выбранных файлов. Для папки или stream
показывается число выбранных корней, а не выдуманное число вложенных файлов.
Несовместимый stream, другой workspace, занятая цель и перенос в тот же
чейнджлист запрещены. Отмена подтверждения не меняет содержимое сервера.

Действия чейнджлиста → Перенести все файлы использует неизменяемую серверную
выборку и не учитывает фильтры имени, пути и статуса во вкладке Files. Выбери
другой собственный pending-чейнджлист того же stream или явно создай новый.
Для серверной задачи нужен запущенный обработчик files. Удаление непустого
чейнджлиста предлагает перенос файлов или откат; локальные файлы сохраняются.
Удаление не уничтожает pending-правки молча.

Скопируй номер или ссылку на чейнджлист и вставь в Действия → Перейти к
чейнджлисту. Ссылка должна относиться к текущему проекту. Shelf доступен с
обычным правом чтения depot; чужие pending-чейнджлисты остаются закрытыми.
Unshelve для shelf предлагает выбрать цель. Перетаскивание shelf и команда
Unshelve показывают одинаковый предварительный просмотр интеграции до изменения
файлов цели. Отмена просмотра сохраняет shelf и оставляет явно созданную цель
пустой.

## Переключение workspace и место для скачивания

Перед переключением workspace сохрани описание активного чейнджлиста. Если
есть pending-чейнджлисты или серверные задачи, подтверждение оставляет их в
предыдущем workspace; Cancel не меняет активный workspace. Переключение сохраняет
настройки вкладок, колонок и фильтров, но очищает загруженные строки, выделение,
инспектор, review, навигацию и прогресс прежнего workspace. Новый workspace
использует собственный локальный кэш сравнения. Прежние локальные файлы, Have
и серверные задачи сохраняются; вернись в workspace или посмотри задачи в Transfers.

Get Latest/Get Revision проверяет абсолютный корень-папку и свободное место
перед приёмом каждой ограниченной страницы manifest. Расчёт учитывает временные
файлы для замены и уже полученные части больших файлов. Существующие целевые
файлы не считаются свободным местом. При нехватке места в нижнем Log появляется
обычное предупреждение **Sync stopped**, до запроса содержимого этой страницы.
Задача сохраняет требуемое и доступное число байтов; Have ранее подтверждённых
страниц остаётся. Освободи место и повтори тот же выбор — продолжится та же задача.
Это консервативный расчёт на страницу, а не резервирование места от других
процессов. Исключения mappings и проверки коллизий остаются в штатном API.

## Восстановление, новые представления и ограничение памяти

После прерванной операции на панели доступна **Продолжить прерванную операцию**.
Журналы привязаны к серверу, логину, проекту, workspace и локальному корню; тикетов
в них нет. Продолжение использует исходный выбор файлов и штатную задачу/receipt.
Если ответ успешного Submit потерян, читается уже опубликованный чейнджлист;
повторной публикации нет. Для ещё pending Submit снова открывается Review.
Сохраняй кэш workspace и журнал аплоада до завершения восстановления.
Продолжение сохраняет исходный выбор файлов активного workspace; внешние
источники Проводника не импортируются и не копируются.

Rename переносит локальные изменённые байты после успешной штатной операции на
сервере. **Resume local moves** завершает прерванный перенос по тому же receipt;
другой существующий файл назначения не переписывается. Reconcile обновляет
Local/Have/Head и счётчики локальных незалитых файлов/байтов по чейнджлистам.
После локального изменения или новой edit revision счётчик честно требует
Reconcile, вместо повторного обхода миллионов файлов на каждый клик.

Из **View** открываются Workspaces, Streams, Depots, просмотр хранилища и
**Stream Graph**. Списки постраничные; узлы и связи графа ограничены и привязаны
к текущим опубликованным heads. Связи ветвления/слияния содержат реальные
опубликованные чейнджлисты. При изменении heads обнови граф. Масштаб, вкладки,
колонки и сплиттеры сохраняются; глубокие папки и выбранные файлы вне первой
страницы восстанавливаются прямым поиском. В памяти удерживаются до 8192 строк
дерева, до 8000 файлов раскрытых чейнджлистов, до 1000 на чейнджлист и 128
курсоров страниц. Для освобождённой ветки раскрой её заново; полный запрос
продолжает выполняться на сервере.

Внизу видны этапы сканирования, манифеста, аплоада, проверки, подготовки,
скачивания и Submit. Скорость и ETA считаются по реально измеренной передаче
после достаточного интервала и сбрасываются между этапами. Последний чанк
подготовки проверяется чаще; весь миллионный job не опрашивается с этой частотой.
Ошибка показывает путь файла и общую причину в Log; детали сохраняются в Debug Log.

В ТС оставлены просмотр и администрирование. В браузерном файловом проекте нет
checkout, локальных правок, shelve, submit и массовой передачи. Обычные Search
tabs и административный просмотр управляемых записей сохраняются. Браузер не
пытается определять изменения файлов на компьютере пользователя.


### Редактор Depot и администрирование хранилища

В **View → Depots** выберите Depot и нажмите **Редактировать Depot**, либо
**Новый Depot**. Код задаётся при создании и больше не меняется. Можно изменить
название и выбрать настроенный серверный псевдоним Repository или **Хранилище
проекта**. Смена Repository влияет только на новые загрузки: существующие
версии сохраняют прежнее содержимое и расположение. Пути Depot учитывают
регистр. Права чтения/записи `file_depot` настраиваются в **Administration →
Rules**. Создавать и редактировать Depot может только администратор. Переход
между видами файлового workspace сохраняет черновик. Сохранение проверяет
исходную ревизию. При конфликте оставьте введённые данные или выполните
**Сбросить → Отмена → Редактировать Depot**, чтобы открыть актуальную ревизию.

**View → Администрирование хранилища** доступно только администратору. Экран
показывает занятые байты, количество файлов и готовность индекса. Для старого
проекта нажмите **Инициализировать хранилище**, затем **Продолжить индексацию**.
Индекс строится ограниченными пакетами вне потока UI. **Прекратить ожидание**
сохраняет серверную позицию, следующий запуск продолжает работу. Завершите
индексацию перед сохранением политики и очисткой.

Квоты задаются целыми байтами и количеством файлов; ноль означает отсутствие
лимита. Параллельных передач должно быть от 1 до 16. Сроки хранения, карантин и
интервал автоматической очистки задаются в секундах. Нулевой срок хранения
отключает истечение срока записей, нулевой интервал — автоматическую очистку.
Значения квот и ревизии передаются точно, вплоть до 9223372036854775807.
**Сохранить политику хранилища** атомарно применяет черновик с проверкой
ревизии. Обновление не стирает отредактированные поля. При конфликте выполните
**Обновить → Сбросить**, чтобы загрузить текущую политику. Переход в другой вид
сохраняет черновик.

**Пробная очистка** считает неиспользуемые объекты без удаления. **Запустить
безопасную очистку** запрашивает подтверждение и использует сохранённую
политику хранения/карантина; сначала сохраните её изменения. Очистку выполняет
серверный сервис `files`. При отключённом сервисе экран сообщает об этом.
Статус показывает фазу, проверенные объекты, кандидатов и их объём, истёкшие
записи, карантин, удалённые объекты и ошибки. Активный статус обновляется
автоматически, задача сохраняется при повторном открытии вида и приложения.
**Отменить очистку** останавливает активную задачу; уже истёкшие или удалённые
записи не восстанавливаются. Объекты в карантине сохраняются до истечения
заданного срока. Перед физическим удалением нативная очистка повторно проверяет
ссылки. UI не запускает внутренние шаги GC и не принимает произвольные пути
серверной файловой системы.

Перед сменой проекта сохраните или сбросьте черновики Depot и Storage.

Задача со статусом **error** остановлена и сохраняет сообщение об ошибке. После
исправления причины запустите новую **Пробную очистку**, затем при необходимости
подтвердите **Безопасную очистку**. Неудачная задача сама не возобновляется и не
становится успешной после обновления сервера.

В **Reconcile** Handler сочетание **Ctrl+A** выделяет до 1000 загруженных строк,
которые соответствуют фильтрам имени и состояния. **Escape** снимает выделение.
Предпросмотр целевого changelist строится при открытии **Добавить в changelist…**
и освобождается при закрытии; выбранные файлы остаются выделенными. Браузерный
Stream предоставляет просмотр и не выполняет локальный Reconcile.

## Задачи проекта без выделения объекта

В полном Менеджере задач кнопка + работает и без выделенного объекта. Она создаёт задачу только для текущего проекта: asset, shot или другой рабочий объект не нужен. Используется стандартный воркфлоу статусов задач; первоначальный исполнитель — текущий пользователь, поэтому задача попадает в «Мои задачи». Отредактируйте и сохраните её обычными средствами, затем открывайте Инспектор задач. В файловом проекте типа Perforce выбирайте её в разделе связи задач с changelist при submit. Если объект выделен, + по-прежнему создаёт задачу этого объекта.

## Рабочие вкладки и метаданные

Рабочие вкладки сохраняют естественную ширину подписей. Если места не хватает,
используйте горизонтальную полосу прокрутки. Закрытие вкладки отделено от её
выбора. Меню представлений открывает доступные файлы, списки изменений, историю
и метаданные.

Выберите рабочую область в списке метаданных, чтобы просмотреть серверную запись.
В Handler доступны также переключение, редактирование и настройка рабочей области.
Браузерный Stream предназначен для просмотра и администрирования: переключение
локальных рабочих областей, маппинги, checkout и Submit остаются операциями Handler.
Граф потоков в браузере поддерживает просмотр и масштабирование; создание и
редактирование потоков выполняются в Handler.
