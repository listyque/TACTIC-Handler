# Контракт Filter Editor

## Формат и серверная семантика

- Рабочая строка legacy имеет вид `(enabled, (column, relation, value), op)`, первая строка использует `begin`, остальные — `and` или `or`.
- Поисковый payload остаётся плоским interleaved-списком tuple и операторов. Скобок и вложенных групп в legacy нет: `pack_tactic_search_view` сохраняет только level `0`.
- Набор операторов берётся из `tactic_classes.get_match_list_by_type`; QML не добавляет собственных операторов.
- Preset хранится в `config/widget_config` с `category=search_filter`, текущим `search_type`, `view=link_search:<preset>:<tab>` и XML/JSON форматом `pack_tactic_search_view`.
- QML разбирает `search_ops` при повторном открытии и сохраняет порядок и смешанные AND/OR. Это исправляет потерю OR в legacy `unpack_tactic_search_view`, не меняя серверный формат.

## Реализованные сценарии

| Область | QML |
|---|---|
| Условия и типы значений | Добавление, удаление, enabled, column-aware operator, значение, numeric/boolean validation |
| AND/OR и группы | Смешанный плоский порядок сохраняется; вложенные группы намеренно отсутствуют как в legacy |
| Пустой фильтр | Одна пустая default-строка допустима и превращается в пустой поисковый payload |
| Ошибки | Отсутствующая колонка, неизвестный оператор, пустое значение в сложном фильтре и неверное число блокируют Apply/Save |
| Presets | Асинхронные load, create, update, rename title, duplicate и delete через существующий server pool |
| Повторное открытие | XML/JSON preset восстанавливает enabled, порядок строк и `search_ops` |
| Advanced Search | Apply заменяет модель активной вкладки и выполняет ровно один существующий async search |
| Search options | Title вкладки редактируется в draft и применяется вместе с фильтром |
| Process filter | Child stypes, pipeline processes и builtins; project/tab ignore-словарь совместим с `process_ignore_dict` |

## Интеграция и состояния

- Единственным источником состояния поиска является поисковая вкладка: её имя является именем поиска, а её filter payload — полным набором применённых слоёв.
- Любое действие UI, меняющее отображаемую серверную выборку, должно добавлять, изменять или удалять видимые строки Advanced Search и затем выполнять общий `apply_search_filters`. Скрытая локальная фильтрация уже загруженных `sobjects` не считается поиском.
- Search suggestions, быстрые фильтры, облако тегов и будущие поисковые элементы должны использовать один legacy-compatible формат условий. После их применения пользователь должен видеть соответствующие условия при открытии Advanced Search.
- Несколько условий должны явно сохранять AND/OR и порядок. Если плоского списка недостаточно для требуемой семантики, используется поддерживаемый legacy TACTIC expression, а не отдельная QML-only логика.
- Системные поиски вроде My Tasks могут формировать `_expression`, но выражение остаётся обычным видимым слоем фильтра активной вкладки.
- Controller держит только QML-safe draft records. TACTIC project/stype используются внутри Python и не передаются делегатам.
- Сетевые операции preset выполняются через `env_inst.server_pool`; GUI-поток получает только списки словарей.
- Ответ preset-запроса сверяется с `(project, search_type, tab)`. Запоздалый ответ после смены контекста отбрасывается, а Apply требует повторного открытия редактора.
- Удалённый на сервере preset исчезает после refresh; удаление уже отсутствующей записи завершается безопасным обновлением списка.
- Cancel восстанавливает условия и title snapshot, не меняет Advanced Search и не записывает process filter.
- Apply сохраняет legacy-compatible process ignore, передаёт его workspace-модели, сбрасывает cache/pagination и запускает общий поиск.
- Selected preset не применяется к поиску при выборе: он загружается в draft и требует Apply.

## Результаты проверки

| Сценарий | Статус |
|---|---|
| Пустой / одно условие | реализован |
| Несколько AND / несколько OR | реализован, порядок сохраняется |
| Смешанные AND/OR level 0 | реализован |
| Вложенные группы | намеренно отсутствуют в legacy контракте |
| Неверное значение / отсутствующая колонка | Python validation |
| Удалённый preset | безопасный refresh без восстановления фиктивной записи |
| Смена project/search type/tab | stale-result guard и запрет Apply старого draft |

Ручной проверки с реальным TACTIC требуют права insert/update/delete для `config/widget_config`, отображение pipeline конкретного проекта и совместное чтение одного `process_ignore_dict` legacy и QML интерфейсами.

## Облако тегов

- Локальная post-фильтрация тегов удалена.
- Выбранные теги становятся видимыми строками `<tag column> LIKE %value%` в Advanced Search; несколько тегов соединяются через OR.
- При изменении набора тегов сохраняются остальные строки вкладки, обновляется общий legacy-compatible payload и выполняется обычный серверный поиск.
- Повторный запрос облака исключает созданные им строки из запроса частот, поэтому пользователь может добавить соседний тег, не теряя исходное облако.

## Оставшаяся локальная фильтрация

`QuickFilterCatalog` пока является локальным view-filter для уже загруженных `sobjects`. Оставлять его в таком виде как окончательную реализацию нельзя: status/category/range должны стать обычными строками Advanced Search. Process filter требует подтверждённого TEL expression, связывающего текущий search type со snapshot/process; придумывать такой expression без проверки legacy-семантики нельзя.
